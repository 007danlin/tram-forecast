## Запуск и конфигурация

Поток UI: импортированный ML-пакет → проверенный CSV в памяти backend →
FastAPI → относительный `/api/v2/handoff/*` через Vite/Caddy → React → CSV того же результата.
Backend не десериализует joblib, не обучает модель и не загружает погоду по запросу.
Отдельного сетевого ML-сервиса нет.

Frontend работает на `http://localhost:5173`, backend — `http://localhost:8000`.
Команды установки и запуска — в [README](README.md#получить-и-запустить).
Обычный `docker compose up --build` поднимает карту и интерфейс, но не устанавливает
пакет прогноза. Без пакета UI показывает понятное сообщение о недоступности и повтор;
это ожидаемое состояние, а не синтетический график. Для значений нужен
[импорт release](README.md#подключить-готовый-ml-пакет).
Не запускайте Compose и отдельные процессы на одних портах одновременно.

| Настройка | Назначение |
|---|---|
| `BACKEND_URL` | Серверный адрес Vite proxy; по умолчанию `http://127.0.0.1:8000`, в Compose `http://backend:8000`; процесс имеет приоритет над корневым `.env` |
| `TRAMFLOW_HANDOFF_DIR` | Каталог импортированного release, читается backend из окружения процесса при старте; uvicorn не загружает его из `.env` автоматически |
| `TRAMFLOW_HANDOFF_HOST_DIR` | Абсолютный существующий каталог хоста для `compose.handoff.yaml`; монтируется read-only в `/data/handoff` |
| `SITE_URL`, `TRAMFLOW_NETRC_FILE` | URL сайта и закрытый netrc для HTTPS-проверок updater |
| `TRAMFLOW_SITE`, `TRAMFLOW_ROOT`, `TRAMFLOW_BACKEND`, `TRAMFLOW_AUTH_FILE` | Переменные только защищённого Caddy-шаблона; [инструкция](deploy/access.md) |

Браузер не обращается к Docker-имени `backend`: он использует относительный `/api`.
Swagger `/docs` и `/openapi.json` открываются непосредственно на порту backend;
frontend/Caddy проксируют только `/api/*`. Runtime OpenAPI описывает v1 и handoff,
а не шесть предложенных операций общего draft.

## Frontend и HTTP handoff

При загрузке UI выполняет ready → capabilities → query, фиксируя `forecast_run_id`.
Маршруты, даты и шаги берутся из capabilities. Выбирается первый модельный маршрут
и первый день исторического диапазона. Таймаут чтения — 10 секунд, CSV — 30 секунд.
День отображается по часам, неделя и полный календарный месяц — по дням.
Границы HTTP — `[start,end)` с явным `+03:00`; МСК не зависит от зоны браузера.
Период вне доступного диапазона блокируется до запроса.

| Метод | Результат |
|---|---|
| `GET /api/v2/handoff/ready` | 200 только при готовом snapshot; без него 503 |
| `GET /api/v2/handoff/capabilities` | Версия run, маршруты, даты, шаги, лимиты и ограничения |
| `POST /api/v2/handoff/query` | Почасовые/дневные строки, сумма и покрытие выбранного периода |
| `POST /api/v2/handoff/export` | CSV с теми же filters, обязательными run и `expected_result_id` |

График, таблица и итог используют только ответ API. `null` оставляет разрыв,
`partial` показывает сумму доступных значений, `no_data` не заменяется нулём.
Маршрут № 5 отмечен нулевым baseline, а не отсутствием движения.
При смене фильтров устаревший ответ не отображается; экспорт блокируется до нового
результата. 410 требует обновить доступный run, 409 — повторить запрос перед CSV,
503 — показывает недоступность пакета. Подробные тела запросов, ошибки и ограничения —
в [handoff README](backend/handoff/README.md).

Компоненты AppHeader/FilterBar/Workspace/ForecastCard/TimelinePanel, AnalyticsView
и SettingsPanel обновлены под согласованный вариант C «Вечерняя смена».
Данные по-прежнему используют одно handoff-состояние. На компьютере карточка слева
от карты; на телефоне карта выше карточки. Две темы используют единую компоновку.
Карта поставляется через `network.json`, `schematic.svg` и `schematic.meta.json`
в `frontend/public/map-local/`. Она сохраняет pan/zoom/выделение и не связана с выбором
маршрута прогноза. Остановки, направления, сценарии и численный год в UI недоступны.
Отсутствующая/неполная карта или неверная checksum останавливает сборку.
PDF и инструменты извлечения нужны только автору; шрифт и все runtime-ассеты локальные.

## ML и данные

Метрика — успешные валидации/посадки, не заполненность вагона. Ключ batch —
`route`, `date`, `hour`; числа прогноза — неокруглённые неотрицательные float.
CLI `forecast`/`month` включает обе календарные даты, в отличие от HTTP `[start,end)`.
Конкурсный submission отдельно округляет `floor(x + 0.5)`. Позднее QA-дополнение
задаёт девятимаршрутную область модели, но локальный organizer sample по-прежнему
содержит 10 маршрутов и 14 640 ключей. Поэтому адаптер формирует отдельно
sample-compatible (14 640) и modeled-routes (13 176) candidates, маркирует
scope/contract status и не выбирает финальный формат без согласования.
Диспетчерский CSV не является конкурсным submission.

Модель, реальные данные, погодные snapshots и результаты хранятся вне Git/образов.
Обучение и inference выполняются отдельно; готовый совместимый архив создаёт
`scripts.package_ml_handoff`, импортёр проверяет его и отказывается перезаписывать
release. SHA-256 подтверждает целостность, а не качество модели или подпись автора.

`fetch-weather` получает ERA5 с receipt/checksums, `--offline` проверяет snapshot
без сети. `prepare-weather` нормализует уже полученный JSON. Weather selection
и повторный holdout разделены; config, порядок признаков и q90 сохраняются в артефакте.
Новые отчёты, журналы и артефакты не перезаписывают существующие. По умолчанию
журнал backtest создаётся в `artifacts/experiments/experiment-log.csv`.
Команды и оговорки — в [ML README](ml/README.md), результаты автора — в
[паспорте модели](ml/reports/model-card.md) и [погодном отчёте](ml/reports/weather-groups-2026-09-25.md).
Независимая проверка исходного target и подтверждение часового пояса организаторами
остаются открыты. Реальные CSV и credentials не добавляются для прохождения CI.

QA-обработка 26.09.2026 не меняет HTTP v1/handoff. Модель и отчёт качества
ограничены маршрутами `1,7,11,12,17,25,26,28,50`; нулевой № 5 остаётся только
transport fallback для 10-маршрутного candidate. Backtest на девяти маршрутах
после следующего quality-run выбрал `calendar_interaction_ensemble`: rounded
selection score 0.8505524, повторный validation score 0.8290094. Реализована строгая схема маски
`tramflow-training-mask-v1` и сравнение на одинаковых evaluation rows. Маски
Игоря нет, поэтому очистка не применена и score до/после не заявлен.

Детектор истории зарегистрировал провалы без исправления. Для маршрута 50
14.09.2025: 15 успешных валидаций против reference 7 676,5, 4 устройства;
причина `unknown_unverified`, recovery не применялся. Полный отчёт:
[ml/reports/qa-addendum-2026-09-26.md](ml/reports/qa-addendum-2026-09-26.md).

## Серверная поставка и проверки

`deploy/sync-source.sh --check` выполняет fetch и проверку чистого main;
`--apply` сохраняет backup ref и обновляет исходники. При переписанной истории
переход разрешён только при точном совпадении прежнего дерева с предком нового main.
Сервисы скрипт не перезапускает. Полный порядок — [release.md](deploy/release.md).

`deploy/update.sh` сохраняет handoff mount существующего backend, включая
остановленный контейнер. Явный `TRAMFLOW_HANDOFF_HOST_DIR` выбирает новый release;
если контейнер удалён, путь нужно задать заново. Проверка пакета выполняется новым
образом до замены backend; затем сверяется ожидаемый run напрямую и через сайт.
Сохраняются старые frontend/image и пути release; автоматического отката нет.
Запуск updater допускается из чистого main. Caddy и установка данных — отдельные шаги.

CI проверяет комплектность Git, backend/ML/tooling, runtime OpenAPI, зависимости,
TypeScript и сборку. Compose smoke проверяет synthetic v1 и полный синтетический
handoff через read-only mount, включая восстановление после остановки backend.
У frontend есть HTTP healthcheck: `docker compose up --wait` ждёт ответа страницы,
а не только запуска контейнера. Идемпотентный GET в CI также повторяет временные
ошибки соединения, включая reset при старте; после него API проверяется отдельно.
Отдельный `handoff-browser.yml` проверяет batch → API → UI → CSV, ошибки и responsive.
Две сгенерированные копии ТЗ в `output/` исключены из Git; исходники остаются
в [docs/team-specs](docs/team-specs/README.md), локальные копии не удаляются.
`scripts.check_delivery` продолжает запрещать артефакты и забытые исходники.

Проверки текущих исправлений выполнены на отдельной копии подготовленного Git-дерева:
104 Python-теста (37 backend, 9 integration, 28 ML, 24 tooling, 6 Caddy), OpenAPI,
`pip check`, комплектность, чистые `npm ci`/build и Docker-сборки прошли.
Браузер проверил отсутствие release и восстановление, batch → API → UI → CSV,
ошибки, МСК, клавиатуру и мобильную ширину; отдельно проверен Basic Auth.
Compose проверил v1, 503 без пакета, read-only handoff и API/CSV после остановки
и повторного запуска backend. Тестовый Docker-проект после проверки удалён.
Локальные результаты не подменяют статус GitHub Actions, замеры VPS или качество ML.
Нагрузочные измерения имеют собственные условия и статус в
[протоколе нагрузки](docs/verification-load.md); целевые 200 RPS не следуют из smoke.

## Общие договорённости — Даниэль

Поток текущего UI: константный синтетический пример → `ml.forecast.predict_mock()` через `ml.adapter.predict_for_api_v1()` с проверкой версии → FastAPI → HTTP `/api` через прокси frontend → React-график и таблица.

## Frontend — Артём

React + TypeScript + Vite; одна страница. При загрузке и по кнопке сначала проверяется health, затем запрашивается прогноз. Общий таймаут — 10 секунд.
Есть загрузка, сообщение о неудаче, повтор запроса и явная маркировка тестовых данных. При повторе старый график удаляется, чтобы не выдавать его за свежий ответ.
График и доступная таблица используют только ответ API. Времена показываются с исходным смещением, без преобразования в часовой пояс браузера.
`npm --prefix frontend run build` проверяет TypeScript и собирает `frontend/dist/`.
Над графиком расположена схема трамваев Москвы (`TramMap`), которую приложение рисует само по геометрии линий (`network.json`): pan/zoom, клик по линии выделяет её, без обращений к API и без связи с прогнозом. Схема строится из локального PDF скриптом `scripts/map/extract_lanes.py` в `frontend/public/map-local/`; готовый `network.json` теперь поставляется через Git, а отсутствие полной карты останавливает сборку. На схеме отрисованы точки остановок и подписи (в том числе под углом; тексты получены OCR из PDF скриптом `scripts/map/build_stops.py`, часть поправлена вручную; возможны ошибки). Также нарисованы иллюстрации достопримечательностей и значки метро/МЦК из PDF (`scripts/map/build_icons.py`). Клик по остановке и выбор маршрута целиком — **запланировано, не реализовано**; привязка к прогнозу потребует расширения API и согласования с Толей.
Compose собирает frontend и запускает Vite preview; это средство локальной проверки, не схема production-развёртывания.

```sh
curl http://localhost:8000/api/v1/forecast
```

HTTP 200:

```json
{
  "is_mock": true,
  "unit": "passengers",
  "points": [
    {"timestamp": "2026-01-01T09:00:00+03:00", "value": 12},
    {"timestamp": "2026-01-01T09:15:00+03:00", "value": 18},
    {"timestamp": "2026-01-01T09:30:00+03:00", "value": 15},
    {"timestamp": "2026-01-01T09:45:00+03:00", "value": 24},
    {"timestamp": "2026-01-01T10:00:00+03:00", "value": 21},
    {"timestamp": "2026-01-01T10:15:00+03:00", "value": 16}
  ]
}
```

`is_mock: true` обязателен; `unit: passengers` — условное количество пассажиров, `value` — целое неотрицательное число. Это иллюстративная величина без привязки к остановке, маршруту или фактической агрегации.

Список `points` непустой. Backend проверяет структуру результата через Pydantic.
Если ML-функция бросает исключение или возвращает некорректный результат: HTTP 503, `{"detail":"Forecast temporarily unavailable"}`; подробности пишутся в серверный журнал.
Фильтров и параметров запроса нет.

Импортёр принимает фиксированные пути ZIP:
`artifacts/calendar-hgbt-v1/{model.joblib,metadata.json,feature-schema.json,manifest.json}`
и `artifacts/forecast-for-backend.csv`. Имя каталога внутри ZIP — транспортное
имя, а не гарантия конкретной модели. Новый каталог `calendar-holiday-hgbt`
нельзя просто заархивировать под его новым именем: нужна совместимая упаковка.
CSV имеет разделитель `;` и поля `route,date,hour,prediction,reference_value,lower_90,upper_90,priority_score,status`
в указанном порядке. Импорт не перезаписывает release, ограничивает каждый
входной файл 32 МиБ, CSV — 500 000 строк; произвольные файлы архива не исполняются.
Постоянный `artifacts/ml-handoff-v1` при этом аудите не установлен; ранее
пакет проверялся во временном каталоге. На каждой машине требуется свой импорт.

Качество `calendar-holiday-hgbt` из отчёта Георгия не переносится автоматически
на ранее переданный пакет командира, обученный отдельно. Сверять нужно конкретные
metadata/checksum и отчёт его автора. Обновление исходников ML не меняет готовый CSV.

Суммы и CSV сохраняют дробную точность. Пропуски — null/no_data или partial с
покрытием; нули baseline остаются нулями. Дневные интервалы неопределённости
не вычисляются сложением почасовых. Неделя задаётся семидневным периодом и шагом
day; запрос ограничен 31 днём/10 000 строк. Направления, остановки, сценарии и
численный год отклоняются как неподдержанные. Ранее предложенное округление
перед суммированием не принято и не применяется.

Временной интервал HTTP — `[start,end)` с ISO-временами и обязательной зоной;
границы выровнены по часу/полуночи МСК. В CLI `ml forecast`/`ml month` обе
календарные даты **включены**. Например, CLI `--start 2025-11-01 --end 2025-11-01`
соответствует HTTP от `2025-11-01T00:00:00+03:00` до `2025-11-02T00:00:00+03:00`.
Весь 61-дневный batch нельзя получить одним HTTP query: предел — 31 день.
`route_ids` — 1–100 строковых ID до удаления повторов; справочник брать из capabilities,
а не из художественной карты. Неподдержанный маршрут даёт 404.

Query возвращает нормализованные `filters` с закреплённым `forecast_run_id` и

## ML — Георгий; интерфейс — Даниэль

`from ml.forecast import predict_mock`, затем `predict_mock() -> dict`.
Этот публичный интерфейс сохранён. Backend вызывает его через `ml.adapter.predict_for_api_v1()`: перед inference проверяется `ml.forecast.CONTRACT_VERSION == "synthetic-v1"`. Неизвестная или отсутствующая версия вызывает `IncompatibleForecastContract` и прежний HTTP 503; провайдер не запускается. Pydantic по-прежнему проверяет результат. Это проверка совместимости только синтетического контракта, не loader реальной модели/manifest и не готовность данных. Форма HTTP-ответа и OpenAPI v1 не изменены.
Входов нет; функция не читает файлы, сеть, текущее время и не использует случайность.
Выход — новый словарь точно в формате примера выше. Каждый вызов возвращает одинаковые значения; изменение одного результата не влияет на следующий.
Штатных ошибок нет. Неожиданное исключение передаётся backend, который отвечает 503. Обработку будущих ошибок реальной модели предстоит согласовать отдельно.
HTTP API v1 по-прежнему использует только эту тестовую заглушку. Параллельно
реализован реальный локальный batch-контур `python -m ml`. Его inference не
вызывается из HTTP; готовые прогнозы передаются через описанный выше handoff.

Подтверждённая batch-схема `tramflow-hourly-v1`:

- target — количество успешных валидаций `validation_result == 1`;
- ключ — `route`, календарная `date`, `hour` из `tran_date_time`;
- единица — успешные посадки, не заполненность вагона;
- прогноз модели — неокруглённый `float >= 0`;
- submission-адаптер выдаёт `route;date;hour;prediction`, округляя только при
  экспорте; preflight проверяет выбранный scope, порядок ключей, типы/диапазоны,
  checksum и явный статус конфликта 14 640 sample-строк с 13 176 model-строками;
- внутренний batch дополнительно возвращает `reference_value`, `lower_90`,
  `upper_90`, `priority_score` и `status`;
- ML-загрузчик проверяет checksum файлов manifest перед десериализацией модели;
  затем проверяет версии payload/metadata. Backend использует отдельный CSV-загрузчик.

Batch-команды, зависимости, temporal folds и ограничения описаны в
[ml/README.md](ml/README.md). Текущий выбранный метод — фиксированный operational
ансамбль F01 HGBT с absolute loss и recency-weighted interaction HGBT со squared
loss. На ранних selection folds его rounded score — 0.8505524 против 0.8400868
у прежнего F01-кандидата.
На повторно использованном 61-дневном validation-окне сентября–октября 2025
для девятимаршрутной model scope (13 176 строк)
rounded score — 0.8290094 против 0.8231869 у previous-weekday baseline. Этот
период уже оценивался в PR #2 (`calendar_hgbt`, опубликованный raw score 0.8287),
поэтому pristine holdout не заявляется; текущий addendum-run не выбирал модель
по этому окну. Это оценка автора, не независимый повтор и не результат платформы.
Для артефакта, реальных прогнозов и submission предусмотрен локальный `artifacts/`;
содержимое каталога игнорируется Git, не входит в Docker/backend image и не
гарантируется в новом checkout.

Поддержаны: почасовой день, почасовой batch на 61 день, дневная агрегация и пики
для месяца. Годовой режим возвращает только qualitative scenarios с `value=null`.
Маршрут 5 исключён из области модели; `cold_start_zero_baseline` сохраняется
только в sample-compatible transport-кандидате. Неизвестные маршруты — unsupported. Для внешней
информации отчёты различают `operational` (`available_at <= as_of`) и
`competition_retro` (поздние разрешённые внешние факторы, но никогда не будущий
target). ERA5 F02 с полным часовым покрытием 2025 проверен только во втором
режиме и ухудшил rounded selection score до 0.8332729, поэтому в выбранный артефакт не
включён. F03–F16 остаются candidate/blocked с причинами в
[ml/external-sources.json](ml/external-sources.json). HTTP API v1 и v2 draft не
менялись.

`prepare-weather` принимает уже полученный локальный JSON и создаёт нормализованный
CSV/manifest; `--source-url` сохраняет происхождение, но не скачивает источник.
`backtest` может запускаться без `--weather-factors`, тогда погодный кандидат
отмечается как blocked. Полный CLI и зависимости — в `ml/README.md`.
В `backtest` журнал по умолчанию создаётся в `artifacts/experiments/`; для каждого
локального опыта указывать новый путь, существующий файл не перезаписывается.
На holdout фактическое покрытие номинального 90%-го интервала — 0,8280; интервал
не является гарантией. По актуальному паспорту измерены размер артефакта и время
CLI batch, а не HTTP latency/RPS или RAM сервиса.

## Автоматические проверки — Игорь и Даниэль

`.github/workflows/ci.yml` запускается на каждый push в любую ветку, на открытие/обновление PR и вручную (`workflow_dispatch`). На Ubuntu 24.04 независимо выполняются:

- backend/ML: Python 3.12, установка `backend/requirements.txt` и `ml/requirements.txt`, `pip check`, 37 backend-тестов (контракт и handoff), сверка OpenAPI, 9 интеграционных, 40 ML и 25 tooling-тестов; проверки включают отказ до inference при несовместимой/отсутствующей версии, raw/rounded-метрики, календарные переносы, нормализацию погоды, реестр F01–F16, 61-дневные срезы, ансамбль, QA-маску, submission preflight и инструменты подготовки сдачи;
- frontend: Node.js 22.16.0, `npm ci --prefix frontend`, `npm run build --prefix frontend`;
- Compose: проверка конфигурации, сборка и запуск контейнеров, HTTP-проверка страницы и API через прокси на порту 5173. Результат контейнерного API сравнивается с ML-модулем из текущего checkout.

При сбое Compose журнал контейнеров выводится в Actions; контейнеры всегда останавливаются. Доступ workflow к репозиторию — только чтение, секретов и публикации нет. Новый запуск на той же ветке отменяет устаревший.
Это проверка программной связки, не повторная оценка качества ML. Compose job
проверяет только synthetic v1; backend handoff-тесты используют искусственный пакет.
Есть отдельные 6 Caddy-тестов и браузерный сценарий в `tests/access/`, но workflow
их не запускает. Повтор требует Caddy, а браузерный сценарий — также Playwright,
Chrome и собранный frontend; инструкции в [deploy/access.md](deploy/access.md).
При смене контракта или команд запуска обновляйте workflow вместе с этим документом.

Общая команда smoke после запуска frontend/backend: `.venv/bin/python -m scripts.check_integration --base-url http://127.0.0.1:5173`. Она проверяет HTML, health и точное совпадение прогноза через frontend-прокси с ML текущего checkout; при ошибке завершается ненулевым кодом. В Compose job CI вызывается та же команда через `python3`. Проверка не запускает сервисы и не подтверждает готовность реальной модели.
