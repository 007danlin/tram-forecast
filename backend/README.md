# Backend — Толя

FastAPI вызывает ML внутри своего процесса. Запускайте из корня репозитория.
Вызов проходит через `ml.adapter.predict_for_api_v1()`: несовместимая версия synthetic-провайдера отклоняется до inference с прежним HTTP 503. Ответ затем проверяется Pydantic; формат HTTP v1 сохранён. Этот адаптер ещё не загружает реальные артефакты.
Команды, конфигурация и контракт: [INTEGRATION.md](../INTEGRATION.md).
`requirements.in` фиксирует прямые зависимости; `requirements.txt` фиксирует весь установленный граф. При обновлении пересоздайте lock в чистом окружении и проверьте интеграцию.

## Подготовка v2 — BE-01

[Пакет согласования](contracts/README.md) содержит Pydantic-схемы,
[OpenAPI draft](contracts/generated/openapi-v2-draft.json) и
[синтетические примеры](contracts/generated/examples-v2-draft.json).
Это проект `2.0-draft.1`, не принятый командой. Runtime по-прежнему предоставляет
только v1; draft не регистрируется в приложении и не определяет формат ML/датасета.

```sh
.venv/bin/python -m backend.contracts.openapi --check
.venv/bin/python -m unittest discover -s backend/tests -v
```

После правки схем пересоздайте артефакты командой
`.venv/bin/python -m backend.contracts.openapi`, затем выполните обе проверки
и существующие интеграционные тесты. Новые библиотеки не добавлены.

## Напарникам: что можно использовать сейчас

| Часть | Текущее состояние |
|---|---|
| Работающий сервер | `/api/v1/health` и `/api/v1/forecast`, только синтетические данные |
| Контракт v2 (BE-01) | Схемы, OpenAPI и примеры подготовлены для согласования; BE-01 полностью не закрыт |
| Исправления проверок | ISO-даты с зоной, согласованность качественного режима, границы и длительность строк по шагу времени |
| Реальные данные и расчёты (BE-02..08) | Загрузчик готовых прогнозов, агрегация, CSV, коэффициенты, кэш и нагрузочные измерения ещё не реализованы |

В работающем `/docs` показан только v1. Операции v2 из файла OpenAPI пока
не обслуживаются сервером. Сам факт появления схем в `main` не означает,
что команда согласовала их или что на сервере появился реальный прогноз.

Для знакомства достаточно открыть [примеры](contracts/generated/examples-v2-draft.json):
`query` — запрос, `responses.success` — обычный ответ, `partial` — пропуски,
`empty` — пустая выборка, `stale` — устаревший набор, `scenario` — ручная поправка,
`qualitative` — описание без численного прогноза. Все числа вымышленные;
`result_id` здесь пример строки, а не результат работающего алгоритма хеширования.

## Что нужно согласовать перед подключением

| Участник | Следующее действие |
|---|---|
| Артём | Проверить запросы/ответы и состояния UI; подтвердить закрепление версии при экспорте и предложенный `expected_result_id`. Примеры можно использовать для подготовки UI; переключение на v2 — после появления согласованного сервера |
| Георгий | Передать описание цели, единиц, допустимых агрегаций/горизонтов и пример готового batch; согласовать версии и ошибки. HTTP-схемы не задают новый интерфейс ML |
| Игорь | Передать паспорт данных, проверенные ID/справочники, проект manifest и правила пропусков/покрытия; согласовать фиксацию версии фактов для воспроизводимого CSV |
| Даниэль | Зафиксировать решения CR-01..08 и подтверждения принимающих участников в [журнале](../docs/integration/contract-review.md) |
| Толя | После принятия стыков реализовать загрузку run и первый дневной срез, затем CSV с теми же фильтрами и версиями |

Точный перечень предложений и открытых вопросов — в [пакете согласования](contracts/README.md).
Реальные данные и модельные файлы передаются разрешённым локальным способом,
не добавляются в Git вместе с примерами. Подтверждений участников в репозитории пока нет.

## Проверить после получения изменений

Из корня проекта с установленными зависимостями:

```sh
.venv/bin/python -m unittest discover -s backend/tests -v
.venv/bin/python -m unittest discover -s tests/integration -v
.venv/bin/python -m backend.contracts.openapi --check
```

При последней локальной проверке после исправлений прошли 29 контрактных и
9 интеграционных тестов. Они проверяют схемы и сохранность v1, но не качество
модели и не будущую агрегацию. Результат удалённого CI нужно смотреть отдельно
для конкретного коммита. Следующий совместный результат: один подтверждённый
маршрут и день, одинаковые числа в готовом прогнозе, API, UI и CSV.
