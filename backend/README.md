# Backend — Толя

FastAPI предоставляет сохранённый синтетический v1 и новый API готового ML-пакета.
Запускать из корня репозитория. Общие договорённости: [INTEGRATION.md](../INTEGRATION.md).

## Что работает сейчас

| Часть | Состояние |
|---|---|
| `/api/v1/health`, `/api/v1/forecast` | Прежняя совместимая связка с `predict_mock()` через адаптер; шесть синтетических точек |
| `/api/v2/handoff/ready`, `/capabilities` | Готовность проверенного CSV-пакета, реальные маршруты/даты/ограничения |
| `/api/v2/handoff/query` | Фильтр готового прогноза по маршрутам/периоду, часовой и дневной шаг, покрытие |
| `/api/v2/handoff/export` | CSV тех же значений с закреплёнными forecast_run_id и result_id |
| Общий draft `2.0-draft.1` | По-прежнему отдельное предложение; его шесть операций не подключены к серверу |

**Для Артёма и Даниэля: [способ подключения, серверные пути и команды](handoff/README.md).**
Работающая машинная схема — `/openapi.json`, интерактивное описание — `/docs`.
В текущем frontend пока используется v1; новый график не появляется автоматически.

Пакет командира содержит 14 640 строк на ноябрь–декабрь 2025. Девять маршрутов
с модельным прогнозом; № 5 также доступен с явно обозначенным нулевым baseline.
Метрика — успешные валидации/посадки, не заполненность салона. Направлений и
остановочных прогнозов нет. Исходная временная зона не подтверждена; продуктовая
интерпретация МСК указана в metadata и предупреждениях ответа.

## Запуск с переданным пакетом

Зависимости HTTP: `backend/requirements.txt`; ML-библиотеки для чтения CSV не нужны.
`requirements.in` содержит прямые зависимости, `requirements.txt` — зафиксированный граф.
Реальную модель здесь не десериализуем, обучение/inference остаются у Георгия.

```sh
.venv/bin/python -m backend.handoff.install /absolute/path/tramflow-ml-handoff-v1.zip \
  --output artifacts/ml-handoff-v1
TRAMFLOW_HANDOFF_DIR="$PWD/artifacts/ml-handoff-v1" \
  .venv/bin/python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

Импорт выполняется один раз в новый каталог и не перезаписывает старый.
В рабочем checkout переданный пакет уже импортирован в `artifacts/ml-handoff-v1`.
Без этой переменной v1 работает, а handoff сообщает 503. Файлы в `artifacts/`
не входят в Git или Docker-образ. Для сервера подготовлена отдельная накладка
[compose.handoff.yaml](../compose.handoff.yaml), подключающая каталог только для чтения.
Основной Compose не меняется. Все серверные команды и предупреждение о прежнем
`deploy/update.sh` находятся в [инструкции](handoff/README.md).

## Проверки

```sh
.venv/bin/python -m unittest discover -s backend/tests -v
.venv/bin/python -m unittest discover -s tests/integration -v
.venv/bin/python -m backend.contracts.openapi --check
.venv/bin/python -m backend.handoff.check \
  --base-url http://127.0.0.1:8000 --release artifacts/ml-handoff-v1
```

Последняя команда требует работающий сервер и сверяет его с исходным CSV.
Повторить с адресом frontend на порту 5173 для проверки прокси.
Результаты локальной проверки — в [инструкции handoff](handoff/README.md).
Это проверка интеграции, не качества ML и не производительности; VPS не изменялся.

## Общий контракт v2 и следующие задачи

[Пакет BE-01](contracts/README.md), [OpenAPI draft](contracts/generated/openapi-v2-draft.json)
и [синтетические примеры](contracts/generated/examples-v2-draft.json) остаются для
согласования полного интерфейса. Они не заменяют схему handoff в работающем `/docs`.
После правки draft пересоздать его через `python -m backend.contracts.openapi`.

В текущем handoff частично реализованы BE-02..05: загрузка, выдача/агрегация,
готовность и экспорт. Полное ТЗ ещё не выполнено. Открыты: согласование публичного
округления и коэффициентов, связь с геометрией, общий v2, хранение предыдущих run,
кэш и нагрузочные измерения. Числа API/CSV пока не округляются; правило конкурсного
submission остаётся в ML-адаптере. Один run удерживается до перезапуска, старый
после смены возвращает 410, не новый результат под прежним ID.

| Участник | Следующий шаг |
|---|---|
| Артём | Подключить handoff по памятке, показать baseline/partial/no_data/ошибки и предупреждение о МСК; геометрию не связывать по догадке |
| Георгий | Сохранить manifest и CSV-формат передачи; согласовать публичное округление/сценарии; качество модели подтверждается его отчётом |
| Игорь | Проверить соответствие route_id справочникам карты и сквозной сценарий API/UI/CSV |
| Даниэль | Выполнить серверную установку по инструкции и подтвердить ready, зафиксировать решения CR-01..08 и порядок будущих обновлений |
| Толя | После подключения потребителей — согласованные сценарии/retention и измерения нагрузки |

Наличие кода в ветке не означает публикацию на VPS или подтверждение всех
участников. После крупных изменений обновлять этот README и INTEGRATION.md.
