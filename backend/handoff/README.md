# Передача ML-прогнозов в API

Работающий ограниченный контур для `tramflow-ml-handoff-v1.zip`.
Контракт `ml-handoff-v1`, методы `/api/v2/handoff/*`. Это отдельное совместимое
расширение: старый v1 и несогласованный общий draft v2 не переопределены.
Код модели из архива не запускается; `model.joblib` только проверяется по SHA-256.
Новых библиотек для inference не требуется.

## Проверенный пакет и ограничения

- В переданном пакете 14 640 строк, 10 маршрутов, 1 ноября — 31 декабря 2025.
  Диапазон API: `[2025-11-01T00:00:00+03:00, 2026-01-01T00:00:00+03:00)`.
- Модель: 1, 7, 11, 12, 17, 25, 26, 28, 50. Маршрут 5 тоже доступен, но
  его нули имеют `method=baseline`, `status=cold_start_zero_baseline`.
  Это отсутствие успешной истории обучения, не установленное отсутствие движения.
- Цель — количество успешных валидаций (`validation_result == 1`),
  единица metadata — `successful_boardings`. Это не заполненность вагона.
- Только маршрут и час/день. Нет направления, остановок, геометрии,
  сценарных коэффициентов или численного года. Неподдержанные поля отклоняются.
- `raw_timezone` в metadata не подтверждён. Календарные метки интерпретируются
  в МСК по `product_timezone_contract`; предупреждение возвращается в API.
  Это исторический пакет, не свежий прогноз на текущую дату.
- Значения остаются дробными. Округление submission `floor(x + 0.5)` не переносится
  в API молча; изменение публичного правила требует согласования команды.
- Почасовые lower_90/upper_90 и priority_score передаются из CSV. Метод интервала
  указан в ответе, его фактическое покрытие этой интеграцией не проверялось.
  Для дневных строк границы и priority_score равны null: квантили не суммируются.
- metadata не содержит надёжных generated_at/as_of для batch. Эти даты не
  выдумываются. `imported_at` — только время локального импорта, не выпуска модели.
- В исходном manifest нет CSV. Импорт создаёт `receipt.json` с его SHA-256:
  это контроль целостности после получения, не подпись отправителя и не проверка
  обучения. Проверены model.joblib/metadata/feature-schema против manifest;
  исходные train/test из source_checksums в архиве отсутствуют и не проверялись.

Уточнение пользователя от организаторов: № 5 обязателен в конкурсном submission,
нули разрешены. API сохраняет его baseline. Сам submission в архиве не передан,
поэтому его состав не проверен. Экспорт ниже — пользовательский CSV, не DS submission.

## Локальный запуск

Из корня репозитория с установленным `backend/requirements.txt`:

```sh
.venv/bin/python -m backend.handoff.install \
  /absolute/path/tramflow-ml-handoff-v1.zip \
  --output artifacts/ml-handoff-v1

TRAMFLOW_HANDOFF_DIR="$PWD/artifacts/ml-handoff-v1" \
  .venv/bin/python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

Для уже импортированного пакета выполняется только запуск. Импорт не перезаписывает
существующий каталог: для нового пакета нужен новый путь. В текущем рабочем checkout
пакет уже импортирован в `artifacts/ml-handoff-v1` и исключён из Git.

Импорт читает только пять известных файлов, игнорирует `ml/README.md`/код архива,
не распаковывает произвольные пути и не исполняет joblib. Перед публикацией каталога
проверяются manifest, версии, зерно, единицы, справочник, колонки CSV, статусы,
конечность/знак чисел, границы интервалов и дубликаты `(route,date,hour)`.
Каждый файл ограничен 32 МиБ, CSV — 500 000 строк. Оценка ресурсов для больших
пакетов ещё не проводилась. Receipt и model-файлы сохраняются вместе с CSV.

Сервер загружает весь проверенный snapshot один раз при запуске процесса.
Без переменной либо при ошибке handoff отвечает 503; v1/health продолжают работать.
Ошибка записывается в серверный журнал, пути и traceback в HTTP не выдаются.
Автоматической подмены реального прогноза синтетическим нет.

## Артёму: подключение

Используй относительные URL `/api/v2/handoff/...`. Vite и Caddy уже проксируют `/api`.
Менять frontend этим изменением не стали: прежний экран всё ещё запрашивает v1.
Машинная схема реально работающих методов — `/openapi.json`, просмотр — `/docs`.
Не используй `backend/contracts/generated/openapi-v2-draft.json` для этих методов:
это отдельный, пока не принятый общий проект интерфейса.

1. `GET /api/v2/handoff/ready` — 200 только после загрузки проверенного пакета.
   `model_loaded=false` ожидаемо: API читает CSV, а не выполняет inference.
2. `GET /api/v2/handoff/capabilities` — маршруты/методы, доступные даты, шаги,
   ограничения и `forecast_run_id`. Строковые route_id — номера из данного ML-пакета,
   а не проверенные ID художественной карты. Не связывать их с линиями по догадке.
3. `POST /api/v2/handoff/query` — данные для таблицы/графика и суммарные значения.
4. `POST /api/v2/handoff/export` — тот же срез, закреплённый run и ожидаемый result_id.

Пример суток по часам (body JSON, `Content-Type: application/json`):

```json
{
  "route_ids": ["1", "5"],
  "start": "2025-11-01T00:00:00+03:00",
  "end": "2025-11-02T00:00:00+03:00",
  "resolution": "hour"
}
```

Первый query может не содержать `forecast_run_id`; полученный ответ содержит
его в `filters`. Для остальных запросов просмотра закрепи эту версию до
явного обновления пользователем. Недельный просмотр: `resolution=day`,
`start=2025-11-01T00:00:00+03:00`, `end=2025-11-08T00:00:00+03:00` — 7 строк
на маршрут. Месячный срез выражается точными границами, максимум 31 день за запрос.
Это фильтр готового периода, не обещание нового ML-горизонта.

Ответ содержит `rows`, `total`, `total_scope`, `coverage`, версии, `warnings`,
`limitations`, `filters`, `result_id`. Каждая строка — один маршрут/интервал,
`[start,end)`. Дневное значение — сумма доступных совместимых часов.
Пропущенный час имеет `value=null`, не 0. Неполный день имеет `status=partial`
и покрытие `available_hours/expected_hours`; total_scope=available_only.
Полностью отсутствующие данные: total/value=null, total_scope=no_data.
Подтверждённые нули baseline участвуют в покрытии. Значения за пределами
покрытия пакета явно возвращаются как no_data, не экстраполируются.

Для экспорта возьми `response.filters` и добавь
`expected_result_id: response.result_id`. Получишь UTF-8 CSV с BOM, запятыми,
десятичной точкой и заголовком `X-Result-Id`. Числа не округляются, null — пустая
ячейка. CSV содержит версии/метрику/единицу и те же строки, что query.
Допустимые строковые значения в экспорте формируются сервером; пользовательские
свободные тексты и сырые оплаты не экспортируются.

Ошибки: `error.code`, `error.message`, `error.request_id`; HTTP 422 также содержит
`fields`. 404 — маршрут вне справочника модели, 422 — неверные/неподдержанные поля,
410 — запрошенный run не загружен, 409 — экспорт не соответствует result_id,
413 — слишком много строк, 503 — пакет не готов/расчёт завершился ошибкой.
Не превращай эти ответы в нули. `request_id` также доступен в `X-Request-Id`.

Один процесс удерживает один run до перезапуска. Автоматической горячей смены,
кэша query и гарантии хранения прежних run 24 часа нет. После замены пакета
старый экспорт даст 410; интерфейс должен предложить обновить прогноз.
На несколько реплик устанавливается один и тот же пакет. Разные фильтры клиентов
не сохраняются глобально. `result_id` зависит от полного пакета, нормализованных
фильтров и версии расчёта; сортировка/повторы ID и эквивалентные UTC-даты
не меняют результат. Память/число workers выбирать после измерений.

## Командиру: файлы и запуск на сервере

Предлагаемая раскладка вне Git и образа:

```text
/srv/tramflow-data/incoming/tramflow-ml-handoff-v1.zip
/srv/tramflow-data/releases/ml-handoff-v1/
    forecast.csv
    model.joblib
    metadata.json
    feature-schema.json
    manifest.json
    receipt.json
```

Передай архив на сервер разрешённым способом. Из `/opt/tramflow`, после получения
кода с этим изменением, импорт можно выполнить в backend-контейнере без установки
Python/ML-библиотек на хост. Каталог incoming и архив должны существовать:

```sh
docker compose -f compose.server.yaml build backend
docker compose -f compose.server.yaml run --rm --no-deps \
  -v /srv/tramflow-data:/handoff \
  backend python -m backend.handoff.install \
  /handoff/incoming/tramflow-ml-handoff-v1.zip \
  --output /handoff/releases/ml-handoff-v1

export TRAMFLOW_HANDOFF_HOST_DIR=/srv/tramflow-data/releases/ml-handoff-v1
docker compose -f compose.server.yaml -f compose.handoff.yaml config --quiet
docker compose -f compose.server.yaml -f compose.handoff.yaml \
  up -d --build --wait --wait-timeout 120 backend
curl --fail http://127.0.0.1:8000/api/v2/handoff/ready
curl --fail http://127.0.0.1:8000/api/v2/handoff/capabilities
```

`compose.handoff.yaml` монтирует выбранный каталог в `/data/handoff` только для
чтения и устанавливает `TRAMFLOW_HANDOFF_DIR`. Файлы не копируются в образ.
Существующий healthcheck проверяет v1; после запуска обязательно проверить
handoff/ready отдельно: healthy контейнер ещё не означает готовность прогнозов.
Для локального Docker используй ту же накладку с `compose.yaml`.

Для последующих серверных обновлений backend повторять команду с **обоими**
Compose-файлами и переменной. Прежний `deploy/update.sh` не учитывает эту накладку;
не использовать его без доработки Даниэлем для handoff-развёртывания: пересозданный
backend может потерять mount и отвечать 503. Сам production-сервер этой работой
не изменялся. Замена данных — новый каталог, импорт/проверка, затем смена пути
и перезапуск backend. Предыдущий каталог сохранить для ручного отката.

## Проверки

```sh
.venv/bin/python -m unittest discover -s backend/tests -v
.venv/bin/python -m unittest discover -s tests/integration -v
.venv/bin/python -m backend.handoff.check \
  --base-url http://127.0.0.1:8000 --release artifacts/ml-handoff-v1
```

Последнюю команду повторить с портом 5173 для проверки через frontend-прокси.
Она сравнивает первый день всех маршрутов: исходный CSV, каждый час API,
дневные суммы и экспорт с тем же result_id. Она не оценивает качество модели.

Локально проверено на переданном архиве: 14 640 строк, уникальные ключи,
checksum модели, все 10 маршрутов первого дня через HTTP и Vite-прокси,
совпадение исходных значений и экспорта. 37 backend-тестов и 9 интеграционных
тестов прошли. Конфигурации server/local Compose с накладкой валидны.
Проверочная Docker-сборка остановлена после задержки скачивания базового образа
Python (около трёх минут без прогресса слоя); запуск контейнера не подтверждён.
VPS не изменялся; нагрузочные показатели не измерены.

Следующие задачи: принятие этого способа подключения Артёмом; реальные данные
для карты; согласование округления/сценариев; retention предыдущих версий;
quality endpoint и проверка ML-метрик; замеры нагрузки. Полное BE-01..08
не объявляется завершённым по результатам подключения CSV.
