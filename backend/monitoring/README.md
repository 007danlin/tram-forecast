# Автоматический мониторинг города

Рабочий контур от 26.09.2026: сервер сам получает внешние данные при запуске
и затем по расписанию. Браузер читает готовое состояние, не ходит к внешним API.
Раздел «О данных» показывает значки источников, свежесть, ошибки, записи и ссылки.
Ручные погодные/событийные коэффициенты из продукта удалены. Старый сценарный API
сохранён для совместимости; frontend его не вызывает.

## Источники и проверка доступа

Кандидаты взяты из [реестра Георгия](../../ml/external-sources.json) и
[ранее выполненного исследования](../../docs/team-specs/score-v3-sources.md).
Доступ проверен прямыми запросами 26.09.2026; ответы и receipts находятся локально
в `artifacts/monitoring/probe/`, реальные данные не включаются в Git.

| Категория | Подключение | Частота / когда устаревает | Покрытие и ограничения |
|---|---|---|---|
| Погода | [MET Norway Locationforecast 2.0](https://api.met.no/weatherapi/locationforecast/2.0/documentation), публичный JSON, без ключа | 1 час / 3 часа | Одна точка Москвы 55.7558,37.6173, доступный почасовой горизонт до 72 часов; температура, ветер и осадки следующего часа. Это прогноз модели, не измерения станции |
| Перекрытия | [Дептранс](https://transport.mos.ru/mostrans/closures), HTML без ключа | 30 минут / 2 часа | Карта на текущую дату; адрес, вид ограничения, начало и известный конец по дням. Изменение структуры/неожиданная пустая страница — ошибка, не «0 перекрытий» |
| Изменения движения | [Дептранс. Оперативно](https://t.me/s/DtOperativno), публичный HTML без ключа | 5 минут / 30 минут | Последние текстовые объявления, включая восстановление движения. Полнота всех инцидентов и сроков не заявляется |
| Мероприятия | [KudaGo API v1.4](https://docs.kudago.com/api/), JSON без ключа | 6 часов / 24 часа | Москва, ближайшие 14 дней, до 20 страниц по 100 событий. Покрытие пагинации и городская полнота различаются. Сеансы раздельны; бессрочная экспозиция не получает фиктивных дат |
| Пробки | Численные сводки ЦОДД в [официальной ленте Дептранса](https://t.me/s/DtOperativno) | Вместе с лентой / 2 часа **от публикации** | Городские баллы и средняя скорость, когда опубликованы. Это не непрерывный API дорожных сегментов. Старые сводки помечаются устаревшими даже после успешного обновления страницы |

[Open-Meteo Forecast API](https://open-meteo.com/en/docs) проверен: TCP timeout
из этого окружения, включая короткий запрос и IPv4. Парсер и выбор провайдера
реализованы (`TRAMFLOW_WEATHER_PROVIDER=open_meteo`), но рабочий провайдер по умолчанию
— доступный MET Norway. Погодные архивы Георгия не заменяются этим резервом.
[Open-Meteo Free API](https://open-meteo.com/en/terms) ограничен некоммерческим
использованием. MET требует идентифицирующий User-Agent, кеширование и атрибуцию
[CC BY 4.0](https://api.met.no/doc/TermsOfService); они реализованы. Время следующего
запроса учитывает Expires, If-Modified-Since/304, добавлен случайный сдвиг 30–180 с.
У [KudaGo](https://docs.kudago.com/api/) сохранены прямые ссылки на каждую запись.

[Календарь Дептранса](https://i.transport.mos.ru/perekrytiya) доступен, содержит
текущие ограничения, но часть подробностей — инфографика. Он остаётся проверенной
точкой сверки, не отдельным полным машинным потоком. Основная страница
`transport.mos.ru/mostrans/all_news` вернула HTTP 477; ограничения не обходились.
Новый `mosgortrans.ru/routes/changes/` отдаёт SPA без старой ленты. Доступный старый
официальный сайт проверен: последняя публикация 01.09.2026; его парсер сохранён,
но рабочим источником выбран публичный «Дептранс. Оперативно». Официальный портал
[называет этот канал](https://transport.mos.ru/mostrans/all_news/118176) среди
своих каналов информирования. На прямой проверке лента содержит публикации
26.09.2026, включая объявление на 27 сентября. Telegram API-ключ и аккаунт
не требуются; читается только публичная HTML-страница. Изображения и видео
не распознаются. Последние сообщения не равны полному реестру действующих
инцидентов. Кандидат TomTom остаётся неподключённым: ключ, сегменты Москвы и
архив не проверены; численные сводки ЦОДД не объявляются его эквивалентом.

## Запуск

По умолчанию монитор стартует вместе с `backend.main:app`, даже без ML-пакета.
Единственный процесс владеет каталогом через file lock; один worker Uvicorn.

```sh
TRAMFLOW_HANDOFF_DIR="$PWD/artifacts/releases/calendar-interaction-ensemble-b2" \
TRAMFLOW_MONITOR_DIR="$PWD/artifacts/monitoring/live" \
.venv/bin/python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

`TRAMFLOW_MONITOR_ENABLED=0` отключает сеть и показывает «Мониторинг выключен».
Для Docker добавляется `-f compose.monitoring.yaml`: отдельный именованный volume
сохраняет состояние между restart/recreate. Handoff остаётся read-only в своей
накладке; модель/CSV не изменяются. Это конфигурация для отдельного разрешённого
размещения, публикация этим изменением не выполняется.

Один проход для диагностики в отдельный локальный каталог:

```sh
.venv/bin/python -m backend.monitoring --directory artifacts/monitoring/check
```

CLI также блокирует повторного владельца. Он запускает новый проход явно; для
непрерывного наблюдения нужен backend, который соблюдает сохранённое расписание.
Не запускать множество независимых каталогов против одного провайдера.

## Контракт и хранение

`GET /api/v2/monitoring/status`: состояние пяти источников, даты попытки/успеха/
следующего обновления, TTL, количество записей, покрытие, ошибка, до трёх примеров.
`GET /api/v2/monitoring/records?source_id=closures&offset=0&limit=50`: все записи
постранично, максимум 100 за ответ. Никакого внешнего запроса по HTTP-клику нет.
Записывающего публичного endpoint нет. Ответы `Cache-Control: no-store`.

Каждая запись содержит `source_id/source_url`, UTC `fetched_at`, `published_at`
если известно, `valid_start/valid_end`, точность периода, timezone, место/координаты,
`route_link.status/route_ids/method`, значения, примечание, `information_mode=operational`,
`forecast_effect=not_applied`. Источник, raw SHA, время HTTP и нормализованные записи
хранятся вместе. Неизвестные границы и место — `null/unknown`, связь маршрута —
`unknown`, не пустое множество якобы доказанных влияний. Номер автобуса не
становится номером трамвая. Только явный оборот «трамваи 7 и 50» в собственном тексте сообщения (либо
трамвайная метка старого HTML-парсера) допускает `source_explicit_tram_numbers`;
географических пересечений пока нет. Цитата предыдущего сообщения исключается.
Ссылки на ответ/восстановление сохраняются; частичное открытие улицы не закрывает
автоматически весь исходный инцидент. Сводки ЦОДД выделяются из уже полученного
снимка, не создавая дополнительных запросов к Telegram.

Конец дорожного ограничения «по 27.09» представлен исключающей границей 28.09
00:00 МСК, с точностью `day`: это не доказательство круглосуточного перекрытия.
У старых анонсов Мосгортранса дата списка расходилась с деталями статьи;
начало/конец не выдумываются. В оперативной ленте нормализуется только однозначное
«сегодня/завтра с HH:MM до HH:MM» относительно даты публикации в МСК. Сложные
расписания, неизвестные начало/конец и местоположение сохраняются явно, исходный
текст периода — в `values.period_text`. Публикация сама по себе не задаёт срок
действия. Сообщения «движение открыто/восстановлено» получают `notice_kind=reopening`.
Сеансы KudaGo сохраняют расписание провайдера; длительная выставка не превращается
в круглосуточный поток. У погоды MET осадки относятся к следующему часу, у
Open-Meteo — к предыдущему; семантика записана явно.

Для источника создаётся отдельная версия `snapshots/<UTC>-<id>/`: сырые ответы,
requests.json, records.json, manifest.json. `current.json` заменяется атомарно только
после проверки; при сбое сохраняются прежние записи и отдельный failure.json.
Состояние ошибки и backoff переживают restart. Хранится 48 последних попыток плюс
последний успешный снимок, если он старше; это ограниченный рабочий кеш, не полный
архив для обучения. HTTP ограничен 15 с и 5 MiB, проход — 90 с между запросами;
каждый источник работает отдельно, не блокируя прогноз. 429/Retry-After учитывается,
ошибки увеличивают интервал до суток. TLS-проверка обязательна.

## История 2025 и качество модели

Исторический ERA5 pipeline `ml fetch-weather`, 8760 часов 2025 и его manifests
сохранены. [Погодные эксперименты](../../ml/reports/weather-groups-2026-09-25.md)
и [score v3](../../ml/reports/score-v3-2026-09-26.md) не подтвердили улучшение;
абляция T01 ухудшила результат. В B2 сохранены ранее выбранные календарные компоненты.
Онлайн-снимки 2026 не соединяются с ноябрём–декабрём 2025 и не меняют champion.csv.

Полный архив изменений движения/мероприятий за конкурсные даты не подтверждён;
доступность фильтра в API не доказывает полноту прошлого. Прямо полученные сведения
сегодня не считаются известными на origin 2025. Чтобы включить новый фактор в ML,
нужны as-of датасет, проверенная маршрутная связь, фиксированные временные folds,
метрика и guardrails Георгия. До этого сервис мониторит контекст без коэффициентов.

Отдельная прямая проверка фильтра KudaGo 01.11–31.12.2025 вернула HTTP 200 и
`count=1237`; сохранена только пробная страница, полнота и доступность сведений на
исторический origin не подтверждены. Попытки GET-фильтра карты перекрытий на
01.11/31.12 вернули HTTP 477; форма сайта использует POST, исторический API/архив
этим не установлен. Данные этих проверок лежат отдельно от operational-снимков
в `artifacts/monitoring/probe/historical-receipts.json`.
