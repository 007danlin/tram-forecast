# Подготовка доступа жюри через Caddy

25 сентября 2026. Выбран для локальной подготовки один Basic Auth перед всеми
ресурсами UI/API. [Caddyfile.protected](Caddyfile.protected) — отдельный вариант;
действующий VPS и прежние шаблоны не переключаются автоматически. Включение
и передача закрытых материалов выполняются по отдельной просьбе после принятия Толей.

Нужен Caddy 2.8 или новее: директива называется `basic_auth`. Она проверяет хеш
пароля, при отсутствии/ошибке данных возвращает 401. Использовать только HTTPS.
Основание: [официальная документация Basic Auth](https://caddyserver.com/docs/caddyfile/directives/basic_auth).
Порядок auth → API/static явно закреплён `route` согласно
[документации route](https://caddyserver.com/docs/caddyfile/directives/route).

## Что защищается

Авторизация выполняется до маршрутизации: `/`, JS/CSS, карта, `/api/*`, неизвестные
пути. Затем `/api/*` проксируется без удаления префикса, остальное обслуживает SPA.
Заголовок Authorization удаляется перед backend. Swagger `/docs` и `/openapi.json`
по-прежнему не проксируются существующей серверной схемой; снаружи это fallback
страницы, также под защитой. Отдельных незапароленных health-исключений нет.
Внутренний Docker healthcheck по loopback продолжает работать.

Backend в `compose.server.yaml` уже опубликован как `127.0.0.1:8000:8000`.
Это обязательная часть границы доступа. Локальный `compose.yaml` — отдельная
конфигурация разработки, её не использовать на публичном сервере.
Внутри backend исполняется только synthetic-заглушка; handoff читает локальный
CSV без inference. Отдельного сетевого ML-сервиса и межсервисного логина нет.

## Подготовить закрытый материал

На доверенной машине из корня проекта, указав новый каталог **вне checkout,
каталога статического сайта и каталогов сдачи**:

```sh
.venv/bin/python -m scripts.prepare_jury_access \
  --caddy /absolute/path/to/caddy \
  --output-dir /absolute/private/path/tramflow-jury
```

Родитель каталога должен существовать. Генератор создаёт новый каталог с правами
0700 и три файла 0600, не перезаписывая существующий: `tramflow-users.caddy`
(логин/хеш), `jury.netrc` (для проверки и обновления), `jury-access.txt` (закрытая
инструкция с паролем). Пароль передаётся в `caddy hash-password` через stdin,
не выводится в журнал и не входит в аргументы процесса. Учётные данные случайные,
подготовка не активирует их. Для другого домена есть `--host`.

Генератор отклоняет пути внутри репозитория, `/srv/tramflow*` (включая сборки
и резервные копии), `/opt/tramflow-backups`, а также корня сайта из `TRAMFLOW_ROOT`.
Для другого статического корня передайте `--web-root /absolute/site/root`;
проверка учитывает символические ссылки. Неизвестные генератору публичные
каталоги также не подходят для хранения credentials.

Не добавлять ни один из этих файлов в Git, Docker context, архивы или общий чат.
Сохранить их в закрытом хранилище до очистки временного каталога. Для жюри после
разрешённой передачи достаточно `jury-access.txt`; netrc и хеш — администратору.

## Отдельный этап включения на VPS

Следующие действия — инструкция для будущего разрешённого включения, **не отчёт
о выполненном деплое**. На сервере сначала проверить версию Caddy, владельца
systemd-службы и действующие конфигурации. Для стандартной службы Ubuntu `caddy`:

1. **Сначала доставить обновлённый `deploy/update.sh` в main и на VPS**:
   версия в `/opt/tramflow` должна поддерживать `TRAMFLOW_NETRC_FILE` и проверять
   доступ до изменения backend/статики. Публикация и получение этой версии
   выполняются отдельным разрешённым действием. Сверить файл на VPS с принятой
   версией и проверить синтаксис `bash -n deploy/update.sh`; не запускать деплой
   только ради этой проверки. До выполнения этого условия защиту не включать:
   старый updater получает 401 после переключения сервисов.
2. Доставить закрытые файлы разрешённым способом за пределы `/opt/tramflow`
   и `/srv/tramflow`. Установить хеш-файл в `/etc/caddy/tramflow-users.caddy`
   с владельцем root, группой caddy и правами 0640. Plaintext-файл netrc оставить
   доступным только root (0600), например `/root/tramflow-jury.netrc`.
3. Проверить `docker compose -f compose.server.yaml config`, затем фактическую
   привязку портов контейнера. Backend должен слушаться с хоста только на loopback,
   без `0.0.0.0:8000` и `[::]:8000`. Не менять доступ SSH.
4. Сохранить `/etc/caddy/Caddyfile` в закрытую резервную копию. Проверить кандидата:

   ```sh
   caddy validate --config /opt/tramflow/deploy/Caddyfile.protected --adapter caddyfile
   ```

5. Скопировать кандидата в `/etc/caddy/Caddyfile`, выполнить `systemctl reload caddy`.
   Используется существующий действительный сертификат домена; тестовый `tls internal`
   для публичного адреса не включать. В конфигурации нужны доступные 80/443.
6. Выполнить проверки ниже с другого устройства. При недоступности проверить права
   хеш-файла, журнал Caddy, сертификат, DNS и loopback backend. Не откатываться на
   публичный доступ без принятого решения; прежняя конфигурация может быть открытой.

По умолчанию шаблон использует домен tramflow.ru, root `/srv/tramflow`, upstream
`127.0.0.1:8000`, хеш-файл `/etc/caddy/tramflow-users.caddy`.
Переменные `TRAMFLOW_SITE`, `TRAMFLOW_ROOT`, `TRAMFLOW_BACKEND`, `TRAMFLOW_AUTH_FILE`
предназначены также для изолированных тестов. Если они нужны в production, задавать
их в окружении systemd-службы и проверки Caddy одинаково; export в shell не меняет
окружение уже запущенной службы.

## Проверки доступа и обхода

Из нового приватного окна: без входа страница запрашивает пароль; неверный пароль
не открывает страницу; правильный открывает карту, график и API; после закрытия
всех приватных окон новое окно снова запрашивает вход. Пароль не передавать в URL.

С внешнего устройства без credentials проверить `/`, `/map-local/network.json`,
`/api/v1/health`, `/api/v1/forecast`: ожидается 401 и `WWW-Authenticate: Basic`.
HTTP должен перенаправлять на HTTPS; пароль по HTTP не отправлять.
С закрытым netrc использовать, например:

```sh
curl --fail --silent --show-error --netrc-file /absolute/private/path/jury.netrc \
  https://tramflow.ru/api/v1/health
```

Ожидается `{"status":"ok"}`. `/api/v1/forecast` сохраняет synthetic v1.
Не использовать `-k` на публичном адресе. Проверить прямой `http://PUBLIC_IPV4:8000`
и при наличии AAAA `http://[PUBLIC_IPV6]:8000`: соединение не должно давать ответ API.
Проверить также прямой IP:443 с Host домена без пароля — он не должен обходить auth.
Эти проверки выполняются снаружи VPS; успешный localhost-запрос не проверяет обход.

В протокол записать дату, версию конфигурации/Caddy, имена проверивших, статусы,
привязки IPv4/IPv6, результат нового окна. Пароли, Authorization и netrc не сохранять
в отчёт. Локальные тесты не доказывают настройки firewall/других служб публичного VPS.

## Обновления защищённого сайта

Команда updater из опубликованной базы `2c67772` подходит для synthetic-развёртывания. При установленном
handoff она пока может убрать mount пакета: поддержка `TRAMFLOW_NETRC_FILE`
не добавляет поддержку `compose.handoff.yaml`. Для handoff использовать
[серверные команды с обеими конфигурациями](../backend/handoff/README.md#командиру-файлы-и-запуск-на-сервере)
и отдельно проверять ready; после включения защиты внешние проверки требуют netrc.
Локальная доработка updater требует отдельной приёмки и доставки на VPS.

`deploy/update.sh` принимает необязательный `TRAMFLOW_NETRC_FILE`. Он проверяет
доступ к существующей странице до изменения сервисов; при 401 без credentials
останавливается. Файл авторизации используется также для последующих проверок
HTML/карты/API. Недоступный backend при доступной странице не мешает начать
его восстановление обновлением. При заданном netrc `SITE_URL` обязан использовать HTTPS.

```sh
TRAMFLOW_NETRC_FILE=/root/tramflow-jury.netrc bash deploy/update.sh
```

Эта команда по-прежнему является деплоем и требует отдельной просьбы. Пароль
не передавать через argv, environment или открытый curl `--user`. Проверки
локального synthetic через `scripts.check_integration` остаются без изменения.

## Повторить локальные проверки

```sh
CADDY_BIN=/absolute/path/to/caddy .venv/bin/python -m unittest discover -s tests/access -v
```

Тесты поднимают только loopback Caddy/FastAPI, используют временные credentials
и отдельный локальный CA, проверяя его сертификат. Они не устанавливают CA в
системное доверие, не обращаются к VPS и завершают процессы при выходе.
Без Caddy команда завершается ошибкой; отсутствие проверки не выдаётся за успех.
Браузерный прогон собранного frontend описан в [протоколе](../docs/integration/qa-2026-09-25/verification.md).
