# TramFlow — прогноз спроса на трамвайные маршруты

TramFlow помогает диспетчеру увидеть, на каком маршруте и в какое время ожидается больше посадок. Можно выбрать день, неделю или месяц, сравнить часы, проверить ручной сценарий и скачать результат в CSV.

**Для жюри:** [комплект сдачи и порядок запуска](docs/submission-final/README.md) · [тексты шести полей формы](docs/submission-final/submission-fields.md) · [архитектура](docs/architecture.md).

## Какая версия подготовлена

Состояние на 27 сентября 2026 года. Текущий платформенный лидер в [реестре](ml/experiments/platform-leader.json) — **R03, 0,89061**; C01 — резерв. Подготовленный ранее архив остаётся снимком C01/B2:

| Часть решения | Версия | Что подтверждено |
|---|---|---|
| Конкурсный CSV и модель в архиве | **C01, результат 0,89003** | Результат сообщил Даниэль; модель, код и CSV связаны контрольными суммами. [Паспорт поставки](docs/submission-final/model-current.md) |
| Веб-приложение и Docker inference | **B2, результат CSV 0,84260** | Проверены расчёт из весов, API, интерфейс и экспорт. C01 в веб ещё не установлен |
| Новая конкурсная модель | **R03, результат 0,89061** | Зафиксирована в реестре; перенос в веб и новый комплект выполняется отдельно |

Модель предсказывает **успешные посадки**, а не заполненность вагона. Текущий набор прогнозов покрывает 1 ноября — 31 декабря 2025 года. Девять маршрутов имеют модельный прогноз; № 5 передаётся с нулями по принятому условию конкурса. На карте значения относятся ко всему маршруту. Остановочная детализация пока недоступна.

## Запуск для жюри

Проще всего скачать полный комплект, распаковать и выполнить [короткую инструкцию Docker Compose](docs/submission-final/web-launch.md). Он содержит исходники и отдельный пакет прогноза. Для первого запуска нужен интернет для загрузки зависимостей.

Если есть только исходники, команда ниже запускает интерфейс на [localhost:5173](http://localhost:5173), но для графиков нужно отдельно подключить ML-пакет:

```sh
docker compose up --build
```

### Подключить готовый ML-пакет

Из корня исходников, с Docker Engine/Desktop и Compose. Укажите абсолютный путь к `demo-handoff.zip` из комплекта. Каталог `artifacts/jury-runtime/release` должен отсутствовать.

```sh
export ML_PACKAGE="/absolute/path/demo-handoff.zip"
mkdir -p artifacts/jury-runtime
docker compose build
docker compose run --rm --no-deps \
  -v "$ML_PACKAGE:/input/package.zip:ro" \
  -v "$PWD/artifacts/jury-runtime:/output" backend \
  python -m backend.handoff.install /input/package.zip --output /output/release
export TRAMFLOW_HANDOFF_HOST_DIR="$PWD/artifacts/jury-runtime/release"
docker compose -f compose.yaml -f compose.handoff.yaml up -d --wait
curl --fail http://127.0.0.1:5173/api/v2/handoff/ready
```

Откройте [интерфейс](http://localhost:5173) и выберите 01.11.2025. Документация API: [Swagger](http://localhost:8000/docs). Без пакета интерфейс сообщает, что прогноз недоступен. Пример запуска на отдельных портах, проверка CSV и остановка — в инструкции жюри.

### Получить и запустить без Docker

Для разработки нужны Python 3.12 и Node.js 22.12+. [Подробные команды](docs/developer-guide.md#получить-и-запустить), [frontend](frontend/README.md), [backend](backend/README.md). Модель и данные передаются отдельно от Git.

## Что умеет сервис

- Показывает день по часам, неделю и месяц по дням, обзор маршрутов и график у карты.
- Выгружает CSV именно выбранного результата, сохраняя его версию.
- Применяет четыре ручные поправки: погода, мероприятия, перекрытия и изменения движения. Базовый прогноз сохраняется отдельно.
- Показывает текущий мониторинг городских источников с временем получения и ошибками.
- Даёт три качественных сценария на год и план проверки по кварталам. Численный годовой прогноз не заявляется.

Сервис выдаёт заранее рассчитанный прогноз через FastAPI. Обучение и расчёт модели выполняются отдельно. [Источники и их роль](docs/submission-final/external-data.md), [ограничения и развитие](docs/submission-final/limitations.md).

## Производительность

| Что измеряли | Условия | Результат |
|---|---|---|
| Выдачу и агрегацию готового прогноза через HTTP | Локальный Docker, 1 worker, 2 CPU / 4 GiB, 200 запросов/с, 5 минут | **199,967 запросов/с; p95 9,310 мс; 0 ошибок** |
| Ручной сценарий с двумя коэффициентами | Локальный Docker, 2 CPU / 4 GiB, 60 секунд | **199,945 запросов/с; p95 16,042 мс; 0 ошибок** |
| Полный расчёт B2 из весов, 14 640 строк | Docker на VPS Linux AMD64, 2 CPU / 4 GiB, без swap | **10,75–11,26 с; пик RSS до 186,80 MiB** |

p95 — время, быстрее которого выполнены 95% запросов. HTTP-замеры относятся к выдаче готовых данных; они не измеряют скорость расчёта модели. Замеры B2 не переносятся на C01. Новый нагрузочный тест четырёх коэффициентов и HTTP на VPS не выполнялся. [Протоколы и ограничения замеров](docs/submission-final/performance.md).
