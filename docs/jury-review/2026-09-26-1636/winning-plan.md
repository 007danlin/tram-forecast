# План на максимальный результат TramFlow

Основание — [проверенный аудит](jury-audit.md), 26.09.2026, старт 16:36 МСК. Цель — увеличить ожидаемые баллы и убедительность защиты до **27.09, 23:59 МСК** по предоставленным правилам. На старте около 31 ч 23 мин. Состояние платформы и остаток попыток ещё нужно проверить. Это план следующего этапа, не отчёт о выполненных доработках.

**Приоритет:** сначала воспроизводимый champion и комплект сдачи, затем коэффициенты, год и полезное диспетчерское демо. Георгию — один ограниченный новый опыт по № 50. Наибольший предсказуемый резерв сейчас находится вне повторения уже проигравших ML-серий.

## 1. Три сценария

| Сценарий | Что жюри получает | Оценка и условия |
|---|---|---|
| Сдать сейчас | Рабочий сайт со старым release; корректный новый DS CSV; load-протокол; несвязанный A1 и устаревшие инструкции/ZIP | **19/29, диапазон 17–22**, условно при подтверждении 0,84260. Питч не оценён. Доступность всех материалов и чистый запуск не доказаны |
| Лучший реалистичный план | Приняты D0/G0, D1, D2, D3, D4; G1 ограничен по времени и может закончиться no_improvement | **22–24/29** при K1=8; целевой результат отрепетированного питча **7–9/10**; ориентир **29–33/39**, не обещание. Нужны согласованная работа FE/BE и подтверждённые артефакты |
| Путь к 39/39 | Всё выше, платформенный score >0,88; все 4 категории источников реально улучшают финальную модель; коэффициенты; полные K3/K4/K5; идеальная защита | **39 возможно только при выполнении всех условий**, сейчас не доказано. Три полезных новых категории и сокращение ошибки >23,76% за оставшееся время нельзя включать в гарантированный план |

Реалистичный диапазон получается из K1=8, K2=5, K3=4–5, K4=3–4, K5=2. Это оценка ревьюера; официальной стоимости каждой кнопки в K3/K4 нет. При подтверждённом переходе >0,88 диапазон вырастет на 2; улучшение 0,84260 до, например, 0,86 такого прибавления не даёт. Дополнительный доказанный источник может дать ещё 1 по своей категории, но не засчитывается до включения и абляции. Не складывать оптимистичные эффекты всех задач поверх максимума раздела.

Если Даниэль работает один, сократить D3 до сводной таблицы и одного маршрутного индикатора; сохранить D0, D1, D2, D4.

## 3. Критический путь и время

`G0 пакет champion → D0 проверка происхождения → финальный handoff/набор версий → D0 чистая сборка → D4 репетиция и комплект → две подтверждённые сдачи`.

D1 и D2/D3 готовятся параллельно только после короткого согласования контрактов с принимающими. G1 работает в отдельном каталоге; не меняет incumbent, пока кандидат не принят. Любая смена champion снова проходит участок G0 → D0 и не выполняется в последний час.

| Окно МСК | Что должно быть принято |
|---|---|
| **26.09 16:36–18:36**, первые 2 ч | Даниэль фиксирует версии и проверяет правила/остаток попыток; Георгий передаёт G0 или конкретный список отсутствующего. D0 исправляет итоговую инструкцию/packager. Согласуются примеры D1, год D2 и минимальный D3 |
| **26.09 18:36–27.09 00:36**, следующие 6 ч | Сквозной D1; качественный год; минимум D3. G1 закрыт результатом или no_improvement, G2 оформлен. Первый чистый запуск комплекта и короткий пробный показ; дефекты собраны в один список |
| **27.09 00:36–10:00** | Запас на отдых и ограниченные исправления; долгие новые серии не запускаются. Если команда продолжает работу — только согласованные блокеры |
| **27.09 10:00–14:00** | Интеграция принятого результата, проверки D1/D2/D3, пересборка из выбранной версии. При смене расчётов — соответствующий локальный нагрузочный smoke/повтор, без стресса публичного сайта |

Заморозка и 20:00 — внутренние решения команды, не новые правила организаторов. При более позднем старте переносить только промежуточные окна, сокращая P2 и D3; резерв сдачи не расходовать. Не требовать бессонной работы как зависимости успеха.

## 4. Приёмка перед заморозкой

1. **Качество/происхождение:** один выбранный manifest; точная связь model → inference → 14 640 строк CSV → submission receipt. Если артефакт B2 не восстановлен, не выдавать старый `model.joblib` за него. Зафиксировать воспроизводимый резерв и прозрачные различия.
2. **Числа:** один маршрут и день, месяц, № 5, неподдерживаемый маршрут; контрольные суммы из установленного пакета совпадают с API и CSV. В D1 дополнительно base=100, коэффициенты 1,1 и 1,2 → 132; reset → 100. Проверить stale export и null/coverage.
3. **Продукт:** переходы день/неделя/месяц/год сохраняют маршрут; год качественный, без скрытого копирования численного прогноза. Сводка и временное значение на карте имеют одинаковую дату/единицу и не называются заполненностью.
4. **Запуск:** скачать будущий сдаваемый архив по предназначенной жюри ссылке, распаковать в чистый путь, выполнить README, дождаться ready, открыть UI и экспорт. Никакой зависимости от developer Downloads, локального `.venv`, кэша Docker или незаявленного пакета на ноутбуке.
5. **Доказательства:** README содержит реальный load-протокол с окружением; архитектура обозначает batch, границы, версии. Список implemented отличен от roadmap. Все A1–A6 открываются в сессии с правами жюри; сырые персональные данные не публикуются.
6. **Защита:** за 5 минут команда показывает законченное действие и объясняет модель/данные/API. Проверен резерв без сети. Каждое сильное утверждение имеет одну открываемую страницу/число/артефакт.

## 5. Две отдельные сдачи

**Data Science:** проверить действующие лимиты: в предоставленном PDF 36 попыток всего / 24 успешных в день, лучшая за всё время. Проверить 14 640 ключей, № 5, часы, integer, hash. Даниэль отдельно разрешает отправку; после неё сохранить ID/время/хеш/score/статус принятия. Не тратить попытки на варианты, проигравшие согласованный локальный отбор; не считать receipt полученным заранее.

**Форма решения:** заполнить A1 модель+код+README; A2 используемые источники; A3 Docker/API/инструкция; A4 архитектура/применимость; A5 производительность/реализованные дополнения; A6 ограничения/развитие. Проверяется заключительная сохранённая форма, поэтому нельзя после хорошей версии оставить незавершённый черновик. Отдельная команда Даниэля на отправку/публикацию, затем повторное открытие и сохранение подтверждения.

Для каждого поля Даниэль хранит: окончательную ссылку, владельца, version/hash, дату проверки доступа, резервную ссылку или локальный комплект. Нынешний аудит не создал публичные ссылки и ничего не отправил.

## 6. Пять минут питча

Предварительный регламент по Q3 — 5 минут + 5 минут вопросов; сверить финальный. Питч строится вокруг подтверждённой версии. Новые функции показывать только после приёмки; иначе использовать честный резервный сценарий.

| Время | Содержание и доказательство |
|---|---|
| 0:00–0:30 | «Прогнозируем успешные посадки по маршруту и часу, чтобы диспетчер заранее выделил периоды для проверки расписания». Сразу назвать исторический период 2025 и отличие от заполненности |
| 0:30–1:10 | 10 месяцев истории, 9 обучаемых маршрутов + нулевой № 5, 61 день без будущего факта. Календарная модель/ансамбль, глобальная метрика, один ясный рисунок batch → API → UI |
| 1:10–2:40 | Демо: обзор маршрутов → выбранный маршрут/час → пик → ручной сценарий → сравнение/CSV → качественный год. При отсутствии D3 начать с выбранного маршрута; при отсутствии D1/D2 прямо назвать ограничение, не имитировать |
| 2:40–3:20 | Качество: 0,84260 с receipt, если получен, иначе «сообщённый результат»; отдельно S1–S4 0,84484 и reused D 0,82901. Показать один baseline и что реально улучшило модель |
| 3:20–4:00 | Производительность: локальные 2 CPU/4 GiB, 200 RPS, p95 9,31 мс, готовый handoff. Одной фразой границы измерения и новый воспроизводимый пакет |
| 4:00–4:35 | Польза и ограничения: выделили период для проверки выпуска/интервалов, но число дополнительных вагонов без вместимости/высадок не рассчитываем. Геопривязка ограничена; погода испытана, не улучшила |
| 4:35–5:00 | Что работает и как продолжить: stop mapping/высадки/ёмкость/новые факторы после хакатона. Завершить одним конкретным результатом демо и ссылкой для проверки |

Глубина 4: корректная цель, валидация, источник, архитектура, пределы. Ответы 3: короткое утверждение + проверяемое свидетельство. Выступление/демо 3: уложиться во время, показать работающий результат, иметь резерв.

**Резерв:** 60–90 секунд записи на финальном release, скриншоты ключевых экранов с run и датой, локальный Compose с тем же пакетом, заранее выгруженный CSV. При отказе сети переключиться за 15 секунд; не продолжать бесконечно перезагружать сайт. Запись маркировать записью. Секреты/сырые события в резерв не включать.

## 7. Неудобные вопросы и короткие ответы

| Вопрос жюри | Честный ответ и опора |
|---|---|
| Почему № 5 всегда ноль? | Нет успешной истории обучения; позднее уточнение допускает нулевой fallback при сохранении sample. Это технический baseline, не утверждение об отсутствии движения; покажем 1464 строки |
| Что означает 0,84260? | Глобальный `max(0,1−SAE/Σy)` по конкурсному файлу; не «84% заполненности». Receipt связан с hash; без receipt называем источник сообщения |
| Как округляете? | Смесь считается в float, затем один раз `floor(x+0.5)`; сохраняем raw и rounded metric. UI float-export и конкурсный integer CSV — разные продукты |
| Как прогнозируете 61 день без факта вчера? | Из истории до 31.10 и доступных календарных факторов. В B2 нет подстановки будущего y. Сетка целиком формируется заранее |
| D — независимый holdout? | Нет: сентябрь–октябрь уже использовался. S1–S4 тоже пересекаются. Мы показываем ограничения и не выдаём повторную диагностику за новый blind test |
| Зачем собрали погоду, если не используете? | Провели абляцию; проверенные варианты ухудшили метрику. Выбрали более сильную модель, сохранили отрицательный результат и не просим балл за неиспользуемый фактор |
| Поздняя погода — утечка? | Внешние ретроспективные наблюдения разрешены переданным ответом, target будущего — нет. Operational-доступность оцениваем отдельно; текущий B2 вообще без погоды |
| Где остановочный прогноз? | В target нет надёжной привязки события к остановке, `place_id` — депо. DATA относит stop-level к бонусу. Карта связана номером, не выдаём route total за измерения остановок |
| Схема другого года? | Да, визуальная схема 2026 и target 2025 имеют ограничение применимости; не доказана историческая топология. Маршрутные индикаторы не означают географическую точность спроса |
| Почему год без чисел? | Есть только 10 месяцев истории; годовой сезонный цикл не валидирован. Показываем качественные условия и диапазон применимости, как допускает критерий |
| Чем ручной коэффициент отличается от ML-фактора? | Это явное допущение пользователя поверх базового прогноза, с отдельным результатом и reset. Оно не доказывает улучшение WAPE и не меняет DS CSV |
| Почему сайт и лучший score различались? | Код обновили, модель в read-only handoff сохранилась. Мы ведём отдельные версии; после D0 показываем финальную цепочку либо прямо объясняем разделение |
| 200 RPS — это обучение на лету? | Нет, выдача и агрегация готового прогноза. Локально 1 worker, 2 CPU/4 GiB, p95 9,31 мс; не переносим цифру на VPS или inference |
| Как масштабируется? | Одинаковый immutable пакет на stateless-репликах; версии закреплены в ответе/экспорте. Фактический тест двух реплик показываем только если D5 выполнен |
| Сколько вагонов добавить? | Из посадок этого не следует. Нужны высадки, вместимость, расписание, обороты и ограничения парка. Наш результат выделяет период для проверки, не выдаёт неподтверждённую оптимизацию |
| Почему не исправили провалы № 50? | Причина не доказана; labels не меняем. Проверяем ограниченную origin-safe гипотезу свежего профиля. Если она не прошла правила, сохраняем champion |
| Что дал v3? | Direct/daily/regime реально испытаны и проиграли; no_improvement. Это аргумент выбора incumbent, а не новая модель с тем же названием |
| Кто понимает сгенерированный код? | Каждый владелец объясняет свой путь данных, ошибки и ограничения; на репетиции показываем один запрос от CSV до API/UI. Генерация кода сама по себе не заменяет понимание |

## 8. Что сейчас не делать

- Не повторять v3 direct/daily/regime и погодные W01–W05 без новой проверяемой гипотезы.
- Не обещать 0,90–0,95; не использовать oracle с истинными суточными суммами как прогнозный результат.
- Не менять labels, не удалять ночь/№ 5, не переносить расписание 2026 на 2025 без источника.
