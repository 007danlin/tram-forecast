## Закрытые технические проблемы

| Проблема | Исправление и проверка |
|---|---|
| Успешный локальный запуск мог скрывать забытые файлы | `scripts.check_delivery.py` проверяет обязательные файлы, неотслеживаемые исходники, ссылки документации и исключение локальных данных. Включён в CI; 5 регрессионных тестов |
| Временные PDF/скрипты могли попасть в поставку | `tmp/` исключён из Git и Docker, модельные бинарные файлы дополнительно исключены из Docker независимо от каталога |
| Updater мог отключить ML-пакет | Используется handoff overlay, проверка пакета до замены backend и сверка ожидаемого run после запуска. Путь сохраняется также для остановленного контейнера; 5 тестов и проверка настоящего Docker stop/restart |
| Незакоммиченные новые файлы могли влиять на серверную сборку | Updater отказывается работать при неотслеживаемых файлах приложения, изменённых scripts или `.dockerignore` |
| Переписанная история мешает обычному pull старого VPS | `deploy/sync-source.sh`: fetch/check по умолчанию, отдельный `--apply`, backup ref, fast-forward либо переход только при наличии точно такого же прежнего дерева в новой истории. 4 теста, включая отказ при настоящем расхождении и сохранение локальных файлов |
| Документы подразумевали уже установленный release | Установка пакета описана как отдельное обязательное действие; добавлен [единый порядок поставки](../deploy/release.md), уточнены README и серверная инструкция |
| Контейнеры не были проверены | Собраны backend, frontend и серверная статика из отдельной копии исходников без локальных зависимостей и данных |
| CI проверял только synthetic v1 | Добавлены server/handoff Compose validation и полный синтетический ML-пакет: импорт, read-only mount, API/CSV, остановка и повторный запуск с тем же release |

## Полученные результаты

В финальной изолированной копии исходников прошли **98 Python-тестов**:
37 backend, 9 integration, 28 ML и 24 tooling. OpenAPI соответствует генератору.
Проверка комплектности исходников успешна; конфигурации Compose валидны.
Все shell-скрипты deploy и блоки CI прошли проверку синтаксиса; оба YAML workflow
успешно разобраны. Frontend и backend собраны Docker, серверная статика экспортирована
через `deploy/frontend.Dockerfile`. Это локальные результаты, не удалённый CI.

Изолированный Docker запускался на `127.0.0.1:18080` / `127.0.0.1:15173`,
с read-only mount внешнего release. Проверены:

- исходный пакет из `tram-training`: все 10 маршрутов за первый день,
  точные значения CSV → hourly API → дневные суммы → экспорт;
- явно синтетический полный пакет: та же сверка до и после остановки backend,
  с восстановлением пути release в новой shell-сессии;
- новый `calendar-holiday-priority-v1`: все 10 маршрутов за 1 ноября и
  31 декабря 2025, точное совпадение API и CSV через frontend-прокси.

Новый пакет подготовлен параллельной задачей реализации; его обучение не
повторялось этим аудитом. Здесь подтверждена совместимость поставки, а не качество
модели или нагрузочные показатели. Браузерная проверка помогла обнаружить ранние
проверки асинхронного состояния в тестах; изменения UI оставлены владельцу этой работы.

Пакет для проверенного серверного подключения находится локально, вне Git:


## Последний этап: GitHub и VPS

Во время исправлений другая пользовательская задача отправила изменение дат
истории и commit `1e0bcf6` в `server-deployment`. Этот commit не содержит все
позднейшие исправления. Переписывание истории уже опубликовано, поэтому для старого
checkout VPS подготовлен явный порядок перехода в [deploy/release.md](../deploy/release.md).
Перед окончательной отправкой снова проверить текущие refs и diff.

План применения готовых исправлений:

1. Просмотреть и сохранить исходники/документы/тесты, исключив игнорируемые данные,
   веса, credentials и временные файлы. Отправить ветку, получить успешный CI и
   объединить проверенный результат в `main`.
2. На VPS выполнить предварительную проверку и синхронизацию исходников через
   `sync-source.sh`; прежний commit останется под backup ref.
3. Передать отдельно архив и checksum, импортировать в новый каталог release.
   Запустить updater с `TRAMFLOW_HANDOFF_HOST_DIR`, сохранив старые image/frontend.
4. Подтвердить ожидаемый run через публичный HTTPS, API/CSV и доступность карты.
   До этой проверки VPS не считается обновлённым.

Эти публикационные действия требуют отдельной просьбы согласно `AGENTS.md`.
Автоматический rollback обоих компонентов не добавлен: прежние версии сохраняются,
а восстановление остаётся ручным и описано в инструкции поставки.
