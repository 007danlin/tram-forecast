локальная рабочая папка, HTTPS сайта и чтение VPS по SSH. Проверка не выполняла
commit, push, merge, публикацию, обновление или перезапуск сервисов VPS.

**Чистый `main` позволяет установить и запустить текущее синтетическое демо.**

## Что подтверждено из чистого клона

Клон создан отдельно, без копирования `.venv`, `node_modules`, `dist`, `.env`,
артефактов или иных файлов рабочей папки. Использованы Python 3.12.14 и Node 22.22.2.

- `pip install -r backend/requirements.txt -r ml/requirements.txt` и `pip check` — успешно.
- `npm ci --prefix frontend` и `npm run build --prefix frontend` — успешно.
- Backend: 37 тестов; integration: 9; ML: 17. **Всего 63 теста прошли.**
- `python -m backend.contracts.openapi --check` — успешно.
- Uvicorn и Vite preview запущены на временных localhost-портах. Штатный
  `scripts.check_integration` подтвердил цепочку frontend → proxy → API → synthetic ML.
- Карта через HTTP побайтно совпала с отслеживаемым `network.json`.
  В ней 45 линий, 1098 точек остановок, 424 подписи, 47 достопримечательностей
  и 58 значков метро. PDF и OCR для обычного запуска не нужны.
- Без внешнего ML-пакета `/api/v2/handoff/ready` вернул ожидаемые 503 и
  `artifacts_unavailable`, при этом v1 работал.
- `docker compose config --quiet`, серверный Compose и `bash -n deploy/update.sh` — успешно.
- Битых относительных Markdown-ссылок на файлы в обеих проверенных GitHub-ветках не найдено.

Контейнерная сборка и запуск в этой проверке не выполнялись: локальный Docker
daemon не запущен. Результат удалённого CI не подтверждён: доступные GitHub API
вернули 404, хотя чтение репозитория по SSH работает. Успешные локальные проверки
не выдаются за успешный GitHub Actions run. Реальное обучение, качество модели,
нагрузка и браузерная приёмка интерфейса в этот аудит не входили.

## Что ещё не доставлено

1. **Есть на GitHub, но не в `main`:** комплект Q&A и уточнение организаторов,
   инструкция жюри и материалы защиты, дополнительные ТЗ, `deploy/access.md`,
   `Caddyfile.protected`, генератор доступа, упаковщик материалов сдачи и тесты
   этих инструментов. Обновление updater с поддержкой `TRAMFLOW_NETRC_FILE`
   тоже находится в `server-deployment`. Получатель обычного клона `main`
   этих изменений не получает.
2. **Есть только локально и меняется во время проверки:**
   `docs/team-specs/implementation-priorities.md`, `scripts/package_ml_handoff.py`,
   `frontend/src/handoff.ts`, `deploy/handoff.sh`, изменения frontend, updater
   и сопутствующей документации. Это текущая незавершённая работа, её полнота
   и готовность к публикации этим аудитом не подтверждены. Перечень нужно
   повторно сверить через `git status --short` перед отдельной отправкой.
3. **Намеренно вне Git:** реальные CSV, веса, готовый прогноз, ML release,
   credentials, локальные `output/` и PDF/OCR-промежуточные файлы. Для повторного
   развёртывания реального прогноза оператору нужен отдельно переданный пакет
   и контрольные суммы; установка описана в `backend/handoff/README.md`.
   Для повторного обучения нужен исходный датасет по `ml/README.md`.
4. **Неточность опубликованной инструкции:** `backend/README.md` и
   `backend/handoff/README.md` утверждают, что пакет уже импортирован в рабочий
   checkout. Это не свойство клона: `artifacts/` отсутствует и игнорируется Git.
   При обновлении документов эту фразу следует заменить явным требованием
   отдельного получения и импорта пакета.

В 110 отслеживаемых файлах `main` не обнаружены проверенные шаблоны приватных
ключей и распространённых токенов. Реальные веса/CSV и `.env` в составе этого
дерева не найдены; `ml/reports/experiment-log.csv` является отчётом экспериментов.
Это ограниченная проверка комплектности текущего дерева, не аудит всех секретов
во всей истории Git.

**Риск опубликованного updater:** и `main`, и проверенный коммит
`server-deployment` вызывают Compose без `compose.handoff.yaml`. После установки
реального пакета такой updater может пересоздать backend без mount.
Исправление уже появляется локально, но опубликованной и проверенной частью
поставки на момент снимка не является. Просто получить нынешний `main` и
запустить прежний updater недостаточно для включения реального прогноза.

## Порядок завершения поставки

1. Закончить и проверить текущие локальные изменения; отдельно согласованной
   отправкой включить нужный код и документы в GitHub, затем свести их в `main`.
2. Для готового итогового коммита повторить CI и запуск из чистого клона.
   Не добавлять реальные данные, веса, credentials и временные PDF в коммит.
3. Передать ML-пакет отдельно, импортировать в новый каталог release;
   сохранить предыдущую версию для отката. Использовать updater, который
   сохраняет handoff mount и проверяет готовность именно handoff.
4. Отдельным разрешённым развёртыванием обновить сервер. Проверить commit,
   сборку UI, `/api/v2/handoff/ready`, capabilities, query и совпадение CSV
   через публичный HTTPS-прокси. Без этого синхронизация GitHub не означает
   обновление работающего сайта.
