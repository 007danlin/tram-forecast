Актуализировано 26 сентября 2026. Web-исходники, локальный ML handoff и конкурсный
DS-файл — отдельные результаты. Наличие ZIP и совпадение checksum подтверждают

Checksum не выводится из имени файла: перед передачей вычислите его для локальной копии.

Команда воспроизведения по выбранному локальному артефакту, из корня checkout
с ML-зависимостями и разрешённым реальным sample:

```sh
.venv/bin/python -m ml submission --artifact-dir artifacts/calendar-holiday-priority-v1 \
  --template "$DATASET_DIR/test_submission.csv" --scope sample \
  --output artifacts/submission-review.csv \
  --preflight-output artifacts/submission-review.preflight.json
shasum -a 256 artifacts/submission-review.csv
.venv/bin/python -m ml submission --artifact-dir artifacts/calendar-holiday-priority-v1 \
  --template "$DATASET_DIR/test_submission.csv" --scope modeled_routes \
  --output artifacts/submission-review-nine.csv \
  --preflight-output artifacts/submission-review-nine.preflight.json
shasum -a 256 artifacts/submission-review-nine.csv
```

Пути результатов должны быть новыми. Сохраните вместе CSV, preflight и безопасную
опись версии модели/кода. Sample, raw и веса не включаются в Git или GitHub
attachments; канал передачи конкурсного файла и артефакта согласуется отдельно.
Команда не обучает новую модель и ничего не отправляет на платформу.

## Собрать web-архив

Из Git checkout, после проверки diff и включения собственных исходников в индекс:

```sh
.venv/bin/python -m scripts.package_submission_prep \
  --output-dir output/release/handoff-review-01
```

Для проверки `SHA256SUMS` перейдите в каталог комплекта (имена внутри относительные):

```sh
(cd output/release/handoff-review-01 && shasum -a 256 -c SHA256SUMS)
```

Создаётся новый каталог с `web-handoff-preparation.zip`, `ds-status.md`,
`SHA256SUMS` и `verification.json`. Старое имя `web-synthetic-preparation.zip`
больше не используется: старые архивы сохранены как история и не актуализируются
задним числом. `ds-status.md` — памятка, а не конкурсный CSV.

В ZIP входят только выбранные включённые в Git файлы; untracked/игнорируемые
локальные файлы не собираются обходом каталогов. Читаются текущие байты
отслеживаемых файлов, поэтому `source_commit` обозначает базовый HEAD,
а `source_dirty=true` предупреждает об отличиях рабочего дерева.
Для финальной передачи используйте чистый проверенный commit в отдельной копии.
`MANIFEST.sha256` определяет точные байты каждого файла независимо от HEAD.
Одинаковый состав, байты и состояние источника дают одинаковый ZIP;
timestamps записей фиксированы. Существующий каталог назначения не перезаписывается.

`verification.json` проверяет ZIP CRC, точный список, manifest и соответствие
исходным байтам. Он не запускает приложение и не объявляет конкурсную готовность.
Статус `not_performed_by_packager` относится только к действиям этой команды,
не отрицает существующие отчёты тестов/нагрузки проекта.

Опционально `--ml-git-dir /absolute/path/to/review.git --ml-ref <полный-SHA>`
создаёт `ds-ml-candidate-review.zip` из уже доступного фиксированного commit.
Это код, JSON-конфигурации и отчёты выбранной версии без sample/весов/submission;
метрики и возможности не приписываются ему по имени архива.
