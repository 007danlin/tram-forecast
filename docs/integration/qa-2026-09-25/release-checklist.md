## Собрать локальную копию для передачи на проверку

Из корня проекта:

```sh
.venv/bin/python -m scripts.package_submission_prep \
  --output-dir "output/release/qa-$(date +%Y%m%d-%H%M%S)"
```

Каталог должен быть новым. Получаются `web-synthetic-preparation.zip` с исходниками,
документацией и построчным `MANIFEST.sha256`, `ds-status.md` с незакрытыми условиями
DS, общий `SHA256SUMS` и `verification.json`. Последний подтверждает только
целостность: CRC ZIP, точный список файлов, построчный manifest и совпадение
байтов с выбранными исходниками. Он не является актом готовности продукта.
Архив не включает `.git`, `.venv`, node_modules, dist,
raw, веса, закрытые credentials или содержимое output. В него входят явно выбранные
исходники текущего рабочего дерева, в том числе ещё не закоммиченные изменения.
Проверить список файлов перед разрешённой передачей. Статус DS нельзя сдавать
вместо submission; web-архив обозначен как подготовка synthetic.

Для отдельного архива опубликованного ML-кандидата добавить к команде
`--ml-git-dir /absolute/path/to/review.git --ml-ref 90e207507b5897c8e5813f248fc4abf0183da1fd`.
Git-копия должна уже содержать этот проверенный commit. Получается дополнительный
`ds-ml-candidate-review.zip` с кодом, отчётами автора и `REVIEW-README.md`;
он не содержит датасет/веса/sample и не заменяет сверку sample и не устраняет GH-02..04. SHA закреплён,
чтобы сборка не подхватила незаметно изменившуюся ветку.

Исправленный локальный комплект после ревью: `output/release/qa-2026-09-25-review-fixed/`.
В ML-архиве сохранена версия автора из указанного SHA; в web-архиве — текущее рабочее
дерево с исправлениями. Поэтому локальные уточнения документации входят в web-архив,
а ограничения проверки ML дополнительно записаны в его `REVIEW-README.md`.

Устаревший `output/release/qa-2026-09-25/`, `output/docx/qa-2026-09-25/` и
`output/tramflow-qa-addenda.zip` перенесены с сохранением файлов под
`output/superseded/qa-2026-09-25-before-review/`. Их нельзя передавать как актуальные:
там остаётся отозванное указание по № 5. Новые файлы `output/` игнорируются Git.
