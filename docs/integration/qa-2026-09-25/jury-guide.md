# Инструкция жюри по проверке TramFlow

Версия инструкции: 25 сентября 2026. Доступный в этом комплекте режим —
**синтетическое демо**. Шесть фиксированных точек проверяют связь интерфейса,
API и Python-модуля. Они не являются реальным маршрутным прогнозом, результатом
обучения или измерением реального пассажиропотока.

## Адрес и вход

Адрес веб-демо: [https://tramflow.ru/](https://tramflow.ru/).
Работа домена ранее подтверждалась командой; состояние публичной версии
этой подготовкой повторно не проверено. Защита подготовлена локально и ещё
не включена на сервере.

После отдельно согласованного включения защиты браузер предложит логин и пароль.
Они передаются жюри отдельным закрытым сообщением; в этой инструкции и архиве
решения их нет. Откройте адрес в новом приватном окне и введите выданные данные.
При предупреждении о сертификате остановитесь и сообщите Даниэлю по каналу
организаторов. Для смены учётных данных закройте все приватные окна и откройте новое.

## Что проверить за две минуты

1. Открывается страница и видна маркировка тестовых данных. Дождитесь ответа API.
2. На карте работают перемещение, масштабирование и выделение линии.
   Карта — отдельная схема: клик по линии сейчас не фильтрует прогноз.
3. Сверьте график и таблицу: 1 января 2026, МСК, 09:00 — 12, 09:15 — 18,
   09:30 — 15, 09:45 — 24, 10:00 — 21, 10:15 — 16.
   Это условные синтетические значения без привязки к маршруту.
4. Нажмите кнопку повторного запроса: после загрузки возвращаются те же точки.
5. В том же авторизованном окне откройте
   [health](https://tramflow.ru/api/v1/health) и
   [forecast](https://tramflow.ru/api/v1/forecast): ожидаются `status=ok`
   и `is_mock=true`. Health показывает доступность сервиса, не качество модели.

Выбор дня/недели/месяца, реальные внешние факторы, сценарные коэффициенты,
диспетчерский CSV и качество обученной модели пока не входят в работающий v1.
Их нельзя принимать по этой демонстрации. Если команда передаст новую версию,
инструкция обновляется вместе с подтверждённым run, датами, режимом и замерами.

## Локальный запуск из комплекта исходников

Нужны Docker Engine/Desktop и Docker Compose. Из корня распакованного проекта:

```sh
docker compose up --build
```

Открыть [http://localhost:5173/](http://localhost:5173/). Локальный Compose
предназначен для проверки synthetic и не включает пароль публичного reverse proxy.
Остановить свои контейнеры: `docker compose down`.
Первичная сборка скачивает базовые образы и зависимости; она требует сети или
заранее подготовленного кэша. Отсутствие сетевых запросов модели не означает
возможность первой сборки без интернета. Полностью автономный образ для среды
жюри ещё не подготовлен. Альтернатива без Docker — команды из [README](../../../README.md).

## Если что-то не работает

| Симптом | Действие |
|---|---|
| Окно входа появляется снова / 401 | Повторно проверьте отдельно выданные данные; не присылайте пароль в общий чат |
| Предупреждение HTTPS | Не обходите предупреждение; сообщите адрес и время Даниэлю |
| Ошибка получения прогноза / 503 | Нажмите повтор запроса; если ошибка повторяется, передайте время, адрес и текст ошибки без пароля |
| Нет карты | Обновите страницу; локально проверьте наличие `frontend/public/map-local/network.json` и повторите сборку |
| Долгая первая сборка | Проверьте Docker и доступ к реестрам зависимостей; это не замер скорости inference |
| Нет доступа к сайту | Используйте локальную копию или попросите Даниэля проверить сервер; отдельного подтверждённого резервного хостинга нет |

Проверка отказа выполняется только в своей локальной копии: остановить свой backend,
повторить запрос, увидеть ошибку, восстановить backend и повторить. Общий демо-сервер
для такой проверки не останавливать.
