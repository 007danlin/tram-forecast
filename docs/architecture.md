# Архитектура TramFlow

Дата: 2026-09-25. Владелец: Даниэль. Основание: личное [ТЗ](team-specs/daniel-integration.md), [общий draft](team-specs/shared-contract.md), исходный PDF организаторов, стр. 1-6. Рекомендации стека и требования сдачи из PDF не являются разрешением на публикацию.

Этот документ разделяет реализованный контур и предложение следующего этапа. Рабочий контракт описан в [INTEGRATION.md](../INTEGRATION.md); принятие будущих интерфейсов отслеживается в [листе согласования](integration/contract-review.md). Подтверждений других участников пока нет.

## 1. Реализованный контур

```text
React (frontend/src/main.tsx)
  -> относительный /api/v1/*
  -> Vite proxy (локально) / Caddy (серверная конфигурация)
  -> FastAPI + Pydantic (backend/main.py)
  -> проверка synthetic-v1 (ml/adapter.py)
  -> predict_mock() (ml/forecast.py)
  -> шесть фиксированных синтетических точек -> график и таблица
```

ML исполняется в процессе backend. Адаптер проверяет объявленную версию до вызова провайдера; Pydantic проверяет результат. Неизвестная/отсутствующая версия, исключение и невалидный результат дают прежний HTTP 503. Формат v1, `predict_mock()`, health и логика frontend сохранены.

Служебная константа `CONTRACT_VERSION = "synthetic-v1"` описывает только текущий синтетический ответ. Это не версия датасета, обученной модели или будущего manifest. Проверка декларации версии не заменяет проверку значений и не доказывает качество.

Health подтверждает доступность API. Настоящей модели, готовности реальных данных, CSV и v2 сейчас нет. Серверная конфигурация существует; состояние публичного сервера этой работой не проверяется.

## 2. Предлагаемый MVP после аудита

```text
Локальный raw snapshot
  -> аудит, нормализация, проверенная география [Игорь]
  -> признаки по available_at, обучение, backtest [Георгий]
  -> пакетный inference -> проверенный неизменяемый forecast_run [Георгий + Толя]
  -> чтение run, фильтры, сценарий, агрегация, CSV [Толя]
  -> единый результат: карта, график, таблица [Артём]
```

Даниэль принимает стыки, воспроизводимость и ограничения; Игорь выполняет сквозную QA. Здесь названия наборов логические. Физические файлы, столбцы, целевая величина, ID и зерно остаются **предварительными до аудита Георгия и Игоря**.

Для MVP предлагается сохранить Python/FastAPI, React/Vite и файловый пакетный контур. Новые БД, брокер и отдельный ML-сервис не требуются без измеренной причины. Это сохраняет уже работающий запуск и оставляет HTTP слой независимым от обучения.

| Граница | Производитель | Потребитель | Условие допуска |
|---|---|---|---|
| Raw -> нормализованный snapshot | Игорь | Георгий | Паспорт цели, ключи, зона, наблюдаемость, checksum, отчёт исключений |
| Snapshot -> признаки/модель | Георгий | Batch runner | Версии и порядок признаков; available_at <= as_of; временной backtest |
| Batch -> run | Георгий | Толя | Совместимые версии, область применимости, конечные значения, контрольные примеры |
| Run -> API | Толя | Артём | Принятый OpenAPI, capability/status/error примеры, неизменяемые версии |
| Query -> UI/CSV | Толя | Артём, Игорь | Те же фильтры, run, сценарий, результат и числовая точность |

`predict(request, context) -> ForecastBatch` остаётся предложением. Context передаёт read-only версии явно; HTTP типы не проникают в обучение. Типы, ошибки и загрузчик реального артефакта вводятся после решения CR-01/02/03. Текущий адаптер v1 не принимается за реализацию этого интерфейса.

## 3. Жизненный цикл и воспроизводимость — проект

1. Подготовить candidate в отдельном локальном каталоге. Raw не изменяется на месте.
2. Проверить разрешённое происхождение файлов, checksum, совместимость схем/признаков/модели/географии, покрытие и контрольный batch. Совпадение названий версий само по себе недостаточно.
3. Выпустить целый immutable run; атомарно переключить указатель только после проверок. Конкретный manifest и механизм хранения согласует Толя с Георгием/Игорем.
4. Зафиксировать один run на весь запрос. Чтение нескольких файлов не должно пересекать переключение версии.
5. При ошибке candidate не активировать. Предыдущий run допустим только с его исходными версиями и признаком устаревания. Отсутствие реального run не включает synthetic автоматически.
6. Экспорт читает тот же run, сценарий и версии расчётов/фактов, что просмотр. Удалённый run даёт явную ошибку. Срок удержания и диск согласовать по объёму; предлагаемое в ТЗ удержание 24 часа ещё не обеспечено.

Пакетный runner загружает модель один раз на запуск/версию. В основном пути backend читает готовый run и не обязан держать модель в каждом worker. Если понадобится синхронный inference, отдельно измерить память каждого worker и потокобезопасность модели. Обучение, скачивание источников и тяжёлые join в HTTP не выполняются.

Пути к будущим данным/весам задаются конфигурацией, backend получает read-only volume готовых run. Пока эти настройки и volume **не реализованы**: их имена нельзя использовать как рабочие команды. Сейчас Compose содержит только synthetic, `BACKEND_URL` управляет серверным прокси. `data/`, `models/`, `artifacts/` исключены правилами Git; реальные файлы не добавляются в образ.

Кэш будущего API включает все версии и нормализованные фильтры/коэффициенты. Состояние выбора пользователя остаётся в запросе. Разные реплики читают одинаковые артефакты; изменения active-run не должны подменять запрос с закреплённой версией.

## 4. Минимальный вертикальный сценарий и ворота интеграции

| Этап | Проверяемый результат | Владелец -> принимающий | Состояние |
|---|---|---|---|
| G0: текущая связка | Тесты v1, frontend build, smoke через прокси | Даниэль -> Игорь | Реализованы проверки; результаты в отчёте |
| G1: цель и границы | Паспорт с реальным источником определения y; поддержанные уровни/время | Игорь + Георгий -> Даниэль | Ожидается аудит |
| G2: стыки | Ответы CR-01..CR-08, OpenAPI от Толи, принятые примеры | Владельцы стыков -> потребители | Проект, не принят |
| G3: первый реальный день | Один подтверждённый маршрут, направление если есть, сутки; пять одинаковых ячеек batch/API/UI/CSV | Георгий + Толя + Артём -> Игорь | Требует G1/G2 |
| G4: расширение | Все поддержанные объекты, карта, partial, коэффициенты, месяц/год с честными режимами | Владельцы компонентов -> Даниэль | Не реализовано |
| G5: готовность | QA, нагрузка, ограничения, два комплекта сдачи, репетиция | Все -> Даниэль | Требует измерений |

G3 использует фактический `metric_id`, единицу, ID и период из паспорта. Нельзя заранее выбрать существующий номер маршрута, назвать оплаты пассажирами или заявить остановочную детализацию. День по часам — целевой пользовательский сценарий; преобразование исходного зерна требует обоснования. Если остановки не поддержаны, это ограничение показывается явно.

Сверка G3: выбрать пять ячеек с одинаковыми ключами и полуоткрытыми интервалами; сравнить batch, JSON, таблицу и CSV до округления. Проверить конечную границу, ноль/пропуск и направление. Сменить active-run между просмотром и экспортом: прежний результат или явная недоступность. Математические примеры `[10,20,0,30] -> 60`, сценарий `1.20 -> 72` и partial `40, 75%` уже заданы в [приёмке](team-specs/acceptance.md); это синтетические эталоны, не схема организаторов.

Остальные этапы и ответственность сохраняются по личным ТЗ. UI не пересчитывает прогноз; детали HTTP определяет схема Толи. После смены контракта одновременно обновляются код, примеры, тесты, `INTEGRATION.md` и принимающие компоненты.

## 5. Решения, которые нельзя принять без данных

Определение y/единицы/аддитивности; ключ дедупликации; входные столбцы и типы; зона/задержка поступления; зерно оценки; соответствие маршрута/направления/остановки; геопокрытие; способ обработки null; допустимые горизонты; обучение/feature schema; формат DS-файла. Ответ «не предоставлено» допустим, предполагаемое поле — нет.

Список входов аудита и нерешённых стыков находится в [листе согласования](integration/contract-review.md). Долгосрочный прогноз, коэффициенты, производительность и бизнес-эффект не объявляются проверенными по результатам synthetic smoke.
