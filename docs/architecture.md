# Архитектура TramFlow

Актуализировано 27 сентября 2026. Владелец интеграции — Даниэль.
Рабочие контракты: `tramflow-hourly-v1`, `ml-handoff-v1`, совместимый `synthetic-v1`.
Общий `2.0-draft.1` остаётся предложением в `backend/contracts/`;
он не заменяет runtime OpenAPI. [Текущая интеграция](../INTEGRATION.md).

Локальный комплект принят на исходном B2 calendar_interaction_ensemble: два clean
inference, API/UI/CSV, restart и сценарный smoke. [Протокол и версии](submission-final/b2-acceptance.md).
Позднее B2 опубликован; Docker inference отдельно проверен на VPS AMD64. Новые UI-доработки 27.09 остаются локальными. [Сверка текущей версии](submission-final/final-closure-status.md).

## Работающий контур

```text
Локальный разрешённый датасет и календарь
  → ML: обучение / временная оценка (вне HTTP)
  → сохранённый артефакт с проверенным manifest
  → отдельный Docker CLI inference (без сети; model/sample read-only)
  → новый float batch CSV + отдельный округлённый DS submission
  → независимое сравнение с принятым B2 (после inference)
  → package_ml_handoff → совместимый ZIP
  → handoff.install: проверки → новый локальный release
  → read-only mount / TRAMFLOW_HANDOFF_DIR
  → FastAPI: проверенный snapshot в памяти
  → Vite (локально) или Caddy (серверная конфигурация)
  → React: ready → capabilities → query → график и таблица
  → export с теми же filters, forecast_run_id и expected_result_id
```

HTTP-прогноз не исполняет `model.joblib` и не обучает модель. Отдельные фоновые
сборщики получают текущую погоду, перекрытия, объявления движения и мероприятия;
[контракт мониторинга](../backend/monitoring/README.md). Они не меняют handoff
и не участвуют в вычислении конкурсных значений.

Уточнение 27.09: [переданное объявление о потоковой проверке ML](submission-final/organizer-clarifications-2026-09-27.md)
ставит отдельный вопрос о формате исполнения модели. Соответствие текущего
batch/handoff этому условию не подтверждено. Отдельный контейнерный batch
реализован и побайтно воспроизвёл B2 в двух независимых расчётах; это не проверка
неописанного протокола потока. [Команды](../ml/inference/README.md),
[доказательства и замеры](submission-final/docker-inference-verification.md).

При импорте проверяются пять фиксированных файлов, manifest/checksum, версии,
единица, зерно, ключи CSV, конечность/неотрицательность чисел и статусы.
SHA-256 подтверждает целостность, не качество модели и не подпись отправителя.
Каталог release нельзя перезаписать импортом. При старте backend повторно
проверяет release и удерживает один snapshot до перезапуска процесса.
[Формат и границы](../backend/handoff/README.md).

`/api/v1/*` продолжает обращаться к `predict_mock()` для совместимости и smoke.
Основной UI использует `/api/v2/handoff/*`, отдельный `/api/v2/scenarios/*` и read-only `/api/v2/monitoring/*`; отсутствие реального пакета
возвращает 503, автоматической подмены синтетикой нет. `v1/health` и здоровый
контейнер сами по себе не означают готовность handoff. `/docs` и `/openapi.json`
доступны напрямую на backend; frontend/Caddy проксируют `/api/*`.

## Данные и результат

| Граница | Действующий договор |
|---|---|
| ML batch | Ключ route/date/hour, успешные валидации/посадки, не загрузка вагона; неотрицательные float |
| Handoff query | МСК, полуоткрытый интервал [start,end), hour/day, максимум 31 день |
| UI | День по часам, неделя и календарный месяц по дням; маршруты/диапазон из capabilities |
| Пропуски | null сохраняется; partial показывает доступную сумму и покрытие; no_data не превращается в 0 |
| Export | Те же filters и run; обязательный expected_result_id; числа не округляются |
| Submission | Отдельный адаптер: sample 14 640 / modeled_routes 13 176; финальный scope — полный sample с нулевым № 5, округление floor(x + 0.5) |
| Карта | Локальная схема, pan/zoom/выделение связаны по номеру; панель спроса на уровне маршрута, stop mapping не подтверждён |

В проверенном историческом handoff № 5 — нулевой baseline, а не доказательство
отсутствия движения. Позднее QA исключает № 5 из области модели; сохранение
его нулевой fallback сохраняется в полном sample по уточнению команды.
[QA-дополнение](../ml/reports/qa-addendum-2026-09-26.md) не заменяет уже установленный release.
Исходная зона организаторов остаётся неподтверждённой; продукт интерпретирует
календарные метки в МСК и сообщает это ограничение. Дневные квантили не получают
сложением почасовых интервалов. У backend нет надёжного generated_at/as_of
исходного batch: imported_at обозначает только импорт, эти даты не выдумываются.

Старый run после смены snapshot возвращает 410. Несовпадающий result_id при CSV —
409. UI блокирует экспорт при изменённых фильтрах и игнорирует запоздалый ответ.
Хранение нескольких run/retention и query cache пока не реализованы.

## Запуск, поставка и измерения

Код, карта и lock-файлы находятся в Git. Датасет, модель, ML ZIP, прогноз и
credentials передаются отдельно. Compose с `compose.handoff.yaml` монтирует
проверенный release только для чтения. Обычный Compose без пакета показывает
его недоступность. Команды — в [README](../README.md),
[инструкции жюри](integration/qa-2026-09-25/jury-guide.md) и
[серверной инструкции](../deploy/release.md).

`scripts.package_submission_prep` создаёт web-комплект исходников с manifest и
checksum, включая handoff/load overlays. Отслеживаемые исходники читаются из
рабочего дерева; base SHA и признак изменений явно записаны. Реальные DS CSV и
веса в этот архив не входят. Web-поставка и конкурсный submission — разные
результаты. [Порядок комплектования](integration/qa-2026-09-25/release-checklist.md).

Локальный k6 → Vite → FastAPI: 200 RPS × 5 минут, 2 CPU / 4 GiB, один worker,
p95 9,310 мс, errors/dropped 0. Backend после прогона RSS 64 788 KiB,
VmSwap 0, OOMKilled=false. Условия и ограничения — в
[нагрузочном протоколе](verification-load.md). Это не измерение VPS/Caddy.
Последний датированный серверный результат отдельно описан в
[протоколе развёртывания](verification-deployment-2026-09-25.md).

## Следующий этап — не работающие функции

Остановки/направления, подтверждённая геопривязка и хранение предыдущих run
остаются будущими задачами. Ручной сценарий и качественный год уже реализованы
локально; [контракт и границы](submission-final/contract.md),
[проверки](submission-final/verification.md). CLI `year-scenario` выдаёт только качественные
сценарии с value=null. Наличие draft-схемы или формулировки в ТЗ не означает
доступность этих функций в HTTP/UI.

Для новых интерфейсов сохраняется [лист согласования CR-01…08](integration/contract-review.md).
Не менять единицы, округление, CSV/ZIP-пути и семантику run молча. Новый кандидат
допускается после проверки происхождения, схемы, области, исходного batch,
API/UI/CSV и ограничений. Прежний release сохраняется до приёмки нового.
Неизвестные маршруты не получают случайного ряда, а неподтверждённые линии —
выдуманного остановочного прогноза. Переданные карта и оболочка Артёма `91eb466`
интегрированы с handoff. Незавершённая параллельная ML-серия сохранена отдельно.

## Локальные дополнения D1–D3

Ручной сценарий использует тот же base calculate, затем произведение постоянных weather/event/closures/changes (каждый 0,5–1,5).
Его собственный ID связывает base_result_id, версию алгоритма и коэффициенты.
Отдельный pinned export не меняет DS. Базовый ответ вложен неизменным; сценарные
интервалы null. Метаданные года — статическое описание CLI, числовой год не включён. UI связывает допущения с выбранным маршрутом, полным базовым прогнозом и квартальным планом проверки. Исторический профиль маршрута отдельно не передан: ограничение явно показано, на № 5 и «только схема» персональные сценарии скрыты.
Обзор запрашивает все маршруты одним запросом; временной tick не обращается к API.
Нагрузка сценарного endpoint измеряется отдельно от прежнего base load.
