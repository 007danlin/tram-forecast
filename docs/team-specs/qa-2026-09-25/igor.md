# Дополнительное ТЗ Игорю по данным и проверке

25 сентября 2026. Продолжение DQ-01, DQ-02, DQ-03, DQ-06 и DQ-08. Принимают Георгий и Даниэль. Источники — файлы Q&A с локальным временем.

Твоя первая поставка — уточнённый паспорт данных, проверка полного sample и проверяемое правило технологических валидаций. Она разблокирует модель и общий контракт; повторять уже выполненный аудит не нужно.

## P0 Полный sample и сверка ключей

[Письменный ответ организаторов](../../integration/qa-2026-09-25/submission-clarification.md) сохраняет исходный sample, включая № 5 и все таймстемпы. Указание ожидать сокращённый файл на 13 176 строк отозвано. По аудиту Георгия шаблон содержит 14 640 строк и десять маршрутов; проверь сам файл, версию и checksum.

Сравни ключи, таймстемпы и порядок итогового CSV с исходным sample, проверь дубли/пропуски и конечные неотрицательные целые prediction. Для № 5 допускается описанный нулевой fallback с потерей по метрике. Если строки уже удалены, восстановить их из sample и повторить экспорт. Ночные строки также сохраняются.

**Готово:** есть проверяемый отчёт соответствия полного CSV исходному sample. Область обучаемой модели и fallback отмечены отдельно; отсутствие истории не объявлено отсутствием движения.

## P0 Маска рабочего времени

Исключение технологических валидаций вне работы маршрута подтверждено в **2.docx 02:39–03:08**. Получи расписание нужного исторического периода по маршрутам и датам. Открытые расписания разрешены (**2.docx 08:46**); современное расписание без проверки не доказывает часы работы в 2025 году.

Для маски укажи источник, период действия, маршрут/направление при наличии, временную зону и правило на границах. Ночное движение через полночь учитывай корректно. Часы 05:30–01:00 — пример из вопроса, не готовая общая константа.

Если есть события, фильтруй по времени события до агрегации. Если доступны только часовые labels, отдельно отметь неполные рабочие часы: из суммы 05:00–06:00 нельзя достоверно восстановить часть после 05:30. Не удаляй весь час или половину его значения без согласованного правила. Передай Георгию исходный набор и отдельную маску, не перезаписывай raw.

**Готово:** отчёт содержит количество исключений и изменение суммы цели по маршрутам/часам; есть проверка полуночи и неполного часа. Маска обучения отделена от множества строк официальной оценки.

## P0 Смысл валидаций и ключей

Проверь все способы успешной оплаты, а не только «Тройку»: **2.docx 10:55–11:56**. Утверждение, что неуспешных операций в выгрузке быть не должно, проверь по файлу; найденные отклонения вынеси в отчёт. Прежнее определение validation_result == 1 берётся из README датасета, не из догадки о новой схеме.

Не исключай успешную операцию только из-за признака пересадки или пустого значения этого поля: ответ связывает его с взаиморасчётами (**2.docx 14:32; 3.docx 00:07**). Точную кодировку и значение null проверь в описании данных.

Хеш оплаты не является надёжным ID человека: часть мобильных NFC-устройств меняет его (**3.docx 01:31–02:06**). Не дедуплицируй события по одному хешу и не считай уникальные хеши целевым потоком. Найди подтверждённый ключ операции либо явно оставь ограничение дедупликации.

**Готово:** в паспорте определены успешная операция, пересадка, единица цели и правило дубля; контрольный пример с двумя разными успешными поездками одного хеша сохраняет обе.

## P1 Реестр провалов и расписаний

Различи наблюдённый ноль, подтверждённое отсутствие движения, потерю данных и неизвестную причину. Для заметных провалов сохрани маршрут, период, величину изменения, возможную причину и источник подтверждения. Эксперт отдельно упомянул ремонты и потерю связи: **1.docx 13:24–14:19**.

Передай Георгию кандидаты на восстановление и периоды, которые восстанавливать нельзя из-за реального сокращения движения. Не утверждай, что аномалия вызвана ремонтом, только потому что нашлась похожая новость. Дополнительный массовый сбор всех внешних источников этим Q&A не назначается — продолжай существующий реестр.

## P1 Дополнительная сквозная приёмка

- Конкурсный CSV совпадает с полным sample, включая № 5; обученная модель и нулевой fallback различимы в отчёте. Возможности API согласованы отдельно.
- DS-экспорт целочисленный; есть проверки 2,49, 2,50 и 2,51 по согласованному правилу. Ответ про ближайшее целое — **2.docx 13:46**, правило x,5 команда фиксирует отдельно.
- Сутки по часам и неделя/месяц по дням дают согласованные суммы на одном результате; пропуски и частичное покрытие не скрыты.
- Артём открывает маршрут из общего обзора и переключает день → неделю → месяц без потери выбранного объекта; тестовый предел команды — до двух действий до детализации, не норматив организаторов.
- При включении защиты без учётных данных нельзя получить защищённые прогнозы/CSV; вход жюри проверяется из чистого браузера вместе с Даниэлем.
- Долгий годовой расчёт не блокирует доступ к дню; сбой внешней сети оставляет предусмотренный резервный режим, а не ложные свежие данные.

Проверки прежней защиты от поздних факторов сохраняются для эксплуатационного режима; конкурсное исключение проверяется отдельно. Не бракуй разрешённый ретроспективный эксперимент по правилу другого режима.

## Передача результата

Георгию — паспорт, проверенный набор маршрутов, маска и отчёт исключений, реестр провалов. Толе — справочник доступных объектов и значения статусов. Даниэлю — конфликт sample, вопросы о ночной оценке и результаты приёмки. Артёму — только проверенные связи объектов и причины недоступности.

Данные и сырые отчёты хранятся локально по правилам проекта. В документации и INTEGRATION.md отмечаются фактически выполненные проверки. Commit, push и отправка решения требуют отдельной просьбы.
