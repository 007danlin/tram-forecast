# Общий контракт: данные → ML → API → интерфейс

Статус: проект для принятия пятью участниками. Это внутренние имена и структуры, не описание формата организаторов. Действующий `/api/v1/forecast` и `predict_mock()` остаются неизменными до согласованной миграции.

с конкретными примерами и статусами принятия. [Письменный ответ](../integration/qa-2026-09-25/submission-clarification.md)
сохраняет исходный sample с № 5; область обучения, fallback и ML/API/UI принимаются

и правило целого DS-выхода добавлены в пакет согласования. Описанные ниже правила
публичного API/CSV и горизонтов не меняются молча: итоговый вариант и следующую
версию схем принимают владельцы. Округление только на экране ниже относится
к диспетчерскому представлению и не отменяет отдельное целочисленное DS-требование.

## 1. Сначала определить, что прогнозируем

Игорь и Георгий заполняют паспорт данных по фактическому описанию архива. Даниэль фиксирует решение, Толя и Артём подтверждают понимание показателя.

| Понятие | Правило |
|---|---|
| Целевая величина | Точное определение организаторов, единица, что считается одной записью, способ получения y |
| Валидации | Операции регистрации оплаты; без отдельного основания не равны уникальным пассажирам, посадкам или людям в салоне |
| Посадки/высадки | Показывать только при наличии данных или явно описанной модели оценки |
| Заполненность | Нужны сопоставимые данные о числе людей в конкретном вагоне/на участке и вместимости; суммарные оплаты за час делить на вместимость нельзя |
| Аномальный спрос | Отклонение от сопоставимого исторического уровня; не означает доказанное переполнение |
| Пропуск | Отдельное состояние, не ноль; ноль допустим при подтверждённом наблюдении или правиле расписания |

До получения паспорта в интерфейсе только синтетическое демо с маркировкой. Если доступна лишь маршрутная цель, нельзя распределять её по остановкам и выдавать полученное за наблюдённую/проверенную детализацию. Неподдерживаемый уровень возвращается как недоступный.

## 2. Временные и пространственные правила

- Временная зона UI - `Europe/Moscow`, подпись «МСК». В API - ISO 8601 с часовым смещением; в хранилище допустим UTC при сохранённом правиле преобразования. Наивные даты без зоны отклоняются.
- Все интервалы полуоткрытые: `[start, end)`. Точка - значение за интервал, а не мгновенное измерение. Границы запросов выровнены по выбранному шагу; невыравненные границы отклоняются, а не округляются молча.
- Прогноз «день» - 24 последовательных часовых интервала с выбранного часового начала. «Месяц» в интерфейсе - следующие 30 дней, шаг один день. «Год» - следующие 12 календарных месяцев с первого числа выбранного месяца. Точные даты всегда видны; эти определения согласовать с организаторами при ином требовании.
- `as_of` - момент доступности информации для расчёта; `generated_at` - время выпуска результата; `data_cutoff` - последняя использованная дата фактов. Они различаются, особенно в историческом демо.
- Маршрут, направление, остановка/платформа, участок и версия схемы движения имеют разные строковые ID. Номер маршрута и название остановки не являются ключами.
- Направление обязательно для детализации, если оно известно. Если направление неизвестно в исходных данных, это явно указано; его нельзя восстановить по одному названию остановки.
- Геометрия для карты - WGS84/GeoJSON, порядок координат `[longitude, latitude]`. Порядок остановок задаёт справочник, не сортировка названий или координат.
- Изменение маршрута требует новой версии топологии с периодом действия. Данные старого маршрута не склеиваются с новым без правила миграции.
- Координаты художественной PDF-схемы - отдельная система. Связь с географическими ID хранится в проверяемой таблице соответствий; пиксели нельзя использовать для расстояния до события.

## 3. Минимальные внутренние наборы

Физические форматы выбирает Игорь после изучения архива. Для локального пакетного контура предпочтительны версионируемые файлы Parquet и небольшие JSON-метаданные; это не требование вводить новую БД.

| Набор | Содержание и проверки | Владелец → потребитель |
|---|---|---|
| Паспорт | Файлы, поля, единицы, период, зона, объём, цель, ключ, допустимость публикации, формат DS-отправки | Игорь → все |
| Справочники | ID маршрутов/направлений/остановок/участков, связи, порядок, геометрия, сроки действия | Игорь → ML, backend, UI |
| Нормализованные факты | Интервалы, ключи, `metric_id`, значение или null, статус наблюдения, версия набора | Игорь → Георгий |
| Внешние факторы | Источник, география, valid_start/end, issued_at, available_at, fetched_at, значение, единица, качество | Игорь → Георгий |
| Результат модели | Запрос, строки прогноза, версия модели/признаков/данных, покрытие, предупреждения, область применимости | Георгий → Толя |
| Отчёт качества | Фолды, WAPE-score/MAE, сравнения, ошибки по срезам, абляции, ограничения | Георгий → Даниэль, Игорь |

Каждый пакет имеет manifest: версия схемы, идентификатор набора, контрольные суммы файлов, время подготовки, временное покрытие и число строк. Если исходники не позволяют установить ключ дедупликации, неоднозначность документируется; похожие оплаты не удаляются вслепую.

Соединение признаков допускает только информацию с `available_at <= as_of`. `issued_at` и `fetched_at` не заменяют друг друга. Для исторического источника требуется подтверждённая дата публикации либо консервативное правило задержки. Проверяется отсутствие размножения строк при join.

## 4. Передача модели

Предлагаемый интерфейс Python: `predict(request, context) -> ForecastBatch`. Это будущий интерфейс; `predict_mock()` пока продолжает работать.

- `request`: as_of, start/end, horizon, resolution, metric_id, spatial_level, route_ids, direction_id, entity_ids. Все ID прошли сверку со справочниками.
- `context`: read-only версии нормализованных данных, внешних факторов, feature schema и загруженного артефакта модели; зависимости передаются явно.
- `ForecastBatch`: строки по интервалам/объектам; значения неотрицательные и конечные; пропуски со статусом; описание области применимости и происхождения результата.
- Ошибки домена: некорректный запрос, неподдерживаемый горизонт/уровень, отсутствие данных, несовместимая модель. Толя переводит их в единые HTTP-ошибки.
- Модель загружается один раз при старте или атомарной смене версии. Обучения, скачивания погоды и тяжёлых join в HTTP-запросе нет.

Для демо основной путь - пакетный расчёт неизменяемого `forecast_run_id`, который backend быстро фильтрует и агрегирует. Новая версия становится доступной только после успешной проверки всех файлов. При сбое остаётся предыдущая целая версия с честной отметкой свежести. Отдельные долгие задачи по произвольному запросу - P2, не обязательная очередь заданий в MVP.

## 5. Проект HTTP API v2

Толя реализует Pydantic/OpenAPI как единственный машинный источник схемы. Артём получает TypeScript-типы и синтетические примеры из этой схемы. Таблица ниже - проект операций, а не документация уже работающего API.

| Операция | Назначение |
|---|---|
| `GET /api/v2/capabilities` | Метрики, горизонты, детализация, диапазоны дат, ограничения, источники, коэффициенты, текущий forecast_run_id |
| `GET /api/v2/network` | Версионированные справочники и геометрия; фильтр маршрутов; ETag |
| `POST /api/v2/forecast/query` | Один срез прогноза; карта, график, таблица и summary берутся из общего результата |
| `POST /api/v2/forecast/export` | Тот же запрос и обязательный forecast_run_id; CSV с тем же результатом |
| `GET /api/v2/quality` | Отчёт о модели и внешних факторах для выбранной версии; без реальных строк исходников |
| `GET /api/v2/ready` | Готовность данных и совместимого артефакта; отдельно от существующего health |

Запрос query: `forecast_run_id` (необязателен при первом открытии), `start`, `end`, `horizon` (`day/month/year`), `resolution` (`hour/day/month`), `metric_id`, `spatial_level` (`route/stop/segment`), `route_ids` (непустой список), `direction_id` (null означает явно разрешённое объединение), `entity_ids` (пустой список - все сущности выбранного уровня), `scenario` (null или коэффициенты). Допустимые сочетания сообщает capabilities.

Проект ограничений: до 100 маршрутов и 10 000 строк на query; до 100 000 на потоковый CSV. Толя уточняет лимиты после измерений. Запрос сверх лимита получает ошибку с предложением сузить выбор; молчаливое обрезание запрещено. Фильтры передаются в теле, не прячутся в пользовательской сессии.

Обязательные поля ответа:

| Поле | Семантика |
|---|---|
| `schema_version`, `request_id`, `result_id` | Версия схемы; ID диагностики; хеш нормализованного запроса и версий |
| `forecast_run_id`, `model_version`, `dataset_version`, `network_version` | Неизменяемые идентификаторы воспроизводимости |
| `generated_at`, `as_of`, `data_cutoff`, `timezone` | Время выпуска, доступность информации, свежесть фактов, зона |
| `mode` | `synthetic`, `model`, `baseline` или `qualitative`; сценарность задаётся отдельно |
| `metric_id`, `unit`, `filters`, `scenario` | Что считаем, по чему отобрано и какие поправки применены |
| `coverage`, `warnings`, `factors` | Доля поддержанных ячеек, машинные коды предупреждений, реально использованные источники и их статус |
| `rows`, `summary` | Детализация и сводка на тех же строках без повторного суммирования |

Строка ответа: `route_id`, `direction_id`, `entity_id`, `start`, `end`, `base_value`, `value`, `actual_value`, `reference_value`, `lower`, `upper`, `status`, `method`, `priority`. Числа nullable, кроме доступных прогнозов. `status`: `ok`, `no_data`, `unsupported`, `no_service`; `no_service` требует подтверждения расписанием. `method` показывает model/baseline на уровне строки при смешанном покрытии. Для qualitative `value=null`, дополнительно текст `outlook` и список `assumptions`.

`actual_value` - факт того же показателя/интервала, доступный на дату просмотра; он не участвует в ретроспективном прогнозе после его `as_of`. `reference_value` - сопоставимый исторический уровень, рассчитанный ML без будущих данных. Отсутствие сравнения не заменяется нулём. Интервалы `lower/upper` допустимы только вместе с уровнем покрытия и методом; иначе null.

`summary`: total только для аддитивной цели, peak_interval, peak_value, число проблемных объектов и доля покрытых ячеек. Для частичного покрытия total называется «по доступным данным»; итог по всему запросу не утверждается.

`coverage` - число ожидаемых базовых ячеек с доступным числовым значением, делённое на число всех ожидаемых ячеек выбранного среза. Подтверждённый ноль включается в числитель; no_data/unsupported - нет. Для пустого множества coverage=null. Покрытие внешнего источника измеряется отдельно. `network` принимает `network_version` из выбранного run; frontend не смешивает прогноз со справочником другой версии.

Ошибки v2: `{error: {code, message, request_id, details}}`. 422 - неверные фильтры/коэффициенты или неподдерживаемое сочетание; 404 - неизвестный ID; 410 - выбранная версия более недоступна; 413 - слишком большой объём; 503 - неготовые артефакты. Пустое пересечение корректных фильтров - 200 и пустые rows с предупреждением. SQL, traceback и локальные пути наружу не выдаются.

## 6. Агрегация без искажения смысла

Суммировать можно только непересекающиеся интервалы и сущности аддитивной цели. Маршрутные итоги и их дочерние остановки не суммируются вместе. Одна оплата должна попадать в один канонический факт. Объединение направлений явно указано.

Вместимость, доли, средняя скорость и заполненность не складываются. Для них до реализации нужна отдельная формула и веса. Из маршрутного числа нельзя получить достоверное число пассажиров на участке; если соответствующей цели нет, детализация недоступна.

ML задаёт совместимый способ построения дневных/месячных итогов. Для одного run и одного уровня сумма часовых прогнозов равна доступному дневному итогу в пределах погрешности float. Независимая месячная модель либо согласуется с иерархией, либо явно представлена отдельным сценарием, а не тем же итогом.

Округление только при показе; API и CSV сохраняют числовую точность. Квантили отдельных ячеек нельзя просто сложить и назвать квантилем суммы. Если совместное распределение или калибровка агрегата не реализованы, интервалы агрегата отсутствуют.

## 7. Ручные коэффициенты: единая семантика

P1 реализуется как прозрачная сценарная поправка к уже рассчитанному baseline/model результату. Она не переобучает модель и не объявляется доказанным влиянием погоды или причинным эффектом события.

Формула для выбранных базовых ячеек: `scenario_value = base_value * k_weather * k_event * k_season`. Нейтральное значение каждого коэффициента 1.00; предлагаемый диапазон 0.50-1.50, шаг 0.05. Общий множитель ограничен диапазоном 0.50-2.00; выход за диапазон отклоняется с объяснением, а не скрыто обрезается. Нулевое отключение движения этим механизмом не моделируется.

Поправка действует только в выбранных маршрутах/объектах и интервале; сначала применяется на базовом зерне, затем выполняется агрегация. Смена фильтра сбрасывает сценарий с уведомлением, чтобы старые поправки не переносились незаметно. При k=1 результат точно равен базовому. Пропуски остаются пропусками; null не умножается как ноль.

Если погода уже учтена моделью, интерфейс пишет «Дополнительная ручная поправка к прогнозу». Рядом показываются исходное значение, новое, разница и коэффициенты. Интервалы базовой модели на сценарную кривую не переносятся как калиброванные. Стандартная DS-отправка использует выбранную валидированную модель без пользовательских поправок.

Вычисляет Толя, правила и численные примеры согласуют Георгий и Даниэль. Артём не создаёт второй независимый расчёт для карты или экспорта.

## 8. Один результат на экране и в файле

Карта, график и таблица используют один result_id. При экспорте frontend повторяет те же нормализованные фильтры, scenario и **тот же** forecast_run_id. Backend воспроизводит срез и возвращает X-Result-Id; несовпадение или утрата run - явная ошибка, не подмена новой версией.

CSV: UTF-8 с BOM, запятая-разделитель, десятичная точка, экранирование кавычек/переводов строк. Идентификаторы, времена с зоной, целевая величина/единица, базовое и сценарное значения, статус, коэффициенты и версии включаются в колонки. Опасные текстовые значения, начинающиеся с `=`, `+`, `-`, `@`, обезвреживаются как текст; числовые колонки остаются числами. В пользовательском CSV нет сырых оплат. Формат CSV для платформы DS - отдельный адаптер по фактическому шаблону организаторов.

Ключ кэша включает версии, все фильтры, направление, детализацию, горизонт, временные границы и коэффициенты. Общая mutable-переменная «выбранный маршрут» запрещена. Несколько реплик должны читать одинаковые неизменяемые артефакты; пользовательский результат не зависит от локальной памяти одной реплики.

## 9. Передача между участниками

| Стык | Что передаётся | Условие приёмки |
|---|---|---|
| Игорь → Георгий | Паспорт, manifest, facts, справочники, факторы | Ключи согласованы, join не увеличивает число фактов, available_at проверяем |
| Георгий → Толя | Артефакт, feature schema, metadata, runner, тестовый batch | Загружается с нуля, версии совместимы, прогноз воспроизводим |
| Толя → Артём | OpenAPI, типы, примеры success/empty/error/stale/qualitative | UI не угадывает поля и поддерживаемые возможности |
| Артём → Игорь | Экран, сценарии, сборка, список состояний | Сквозные сценарии приёмки проходят на реальном API |
| Все → Даниэль | Рабочие изменения, инструкции, ограничения, доказательства | Контракты и INTEGRATION.md соответствуют реализации |
