# Георгий Дополнение по QA модели

Дата: 26 сентября 2026. Источник: `georgy-qa-addendum.docx`, переданный
пользователем. Это дополнение новее Markdown-пакета QA от 25 сентября.
Последующее уточнение Даниэля 26.09.2026: организаторы разрешили нулевые либо
придуманные значения № 5. Приняты полный sample и нулевой fallback; ниже
обновлены только затронутые этим решением требования. Новая серия —
[ТЗ v3](georgy-score-v3.md).

## Обязательные изменения

- Обучаемая модель, target-отчёт и заявленная область применимости включают
  маршруты `1, 7, 11, 12, 17, 25, 26, 28, 50`; маршрут 5 в них не входит.
- Фактический `test_submission.csv` проверяется отдельно. Все его 14 640 ключей
  сохраняются, № 5 получает нулевой fallback. Девятимаршрутный вариант допускается
  для диагностики; дополнительное согласование состава submission не требуется.
- Технологические валидации исключаются из обучения только по версионированной
  подтверждённой маске. Диапазон 05:30-01:00 не считается доказанным расписанием.
  Официальные оценочные строки и target не очищаются.
- Raw float сохраняется внутри модели. DS-экспорт использует единый
  `floor(x + 0.5)` для конечных неотрицательных значений; backtest считает
  метрику после того же преобразования.
- Резкие провалы истории регистрируются без автоматического удаления или
  восстановления. Причина не назначается без источника.
- Почасовой результат остаётся источником суток, недели и месяца; агрегация
  выполняется по raw float. HTTP-контракты не меняются без владельцев.

## Фактическая сверка

Локальный sample SHA-256
`71c8126bb51068c936462a170da885bad860fc91a58b3d2ac731876d324d7ec3`
содержит 14 640 уникальных ключей, 61 дату, 24 часа и 10 маршрутов, включая 5.
Девять маршрутов относятся к модели, десять — к полному submission с fallback.
Оба scope поддержаны кодом; устаревший статус конфликта в metadata/preflight
нужно обновить по ТЗ v3. Отправка не выполняется.

Подтверждённой маски Игоря в репозитории и локальных переданных файлах не найдено.
Формат `tramflow-training-mask-v1` реализован, но принимает только правила со
статусом `verified`, источником и часовыми полуинтервалами. Частичные часы
блокируются до пересборки target из raw-событий.

## Открытые согласования

1. Версия, источник, временная зона и точные интервалы маски технологических
   валидаций.
2. Историческая применимость справочников и расписаний. Текущий HTTP/handoff
   сохранён с нулевым fallback № 5, без изменения контракта.

Commit, push, деплой и отправка на платформу этим дополнением не разрешены.
