# Внешние факторы: что подключать и как доказывать пользу

Игорь отвечает за происхождение и воспроизводимое получение; Георгий - за признаки и эффект; Толя - за статусы и выдачу; Артём - за понятное отображение; Даниэль - за приоритеты и представление доказательств.

## 1. Принцип отбора

Полезен источник, который доступен на нужную дату, покрывает маршруты, корректно связан по времени/географии и улучшает проверку на будущих периодах. Количество признаков само по себе не цель. Десять погодных колонок - один погодный источник, а не десять независимых источников для жюри.

Для каждой группы хранить статус: `candidate`, `available`, `integrated`, `validated`, `rejected`. В `validated` переходить только после воспроизводимого сравнения. Отдельно отмечать источники, используемые лишь для визуального контекста или ручного сценария: это не доказательство улучшения модели.

## 2. Кандидаты и очередность

| Группа | Первые признаки | Привязка | Приоритет и резервный вариант |
|---|---|---|---|
| Календарь | Час, день недели, рабочий/выходной, официальный перенос, праздник, сезон | Местное время; календарь конкретного года | P0; время/неделя сразу, специальные дни только по проверенным источникам |
| Погода | Температура, осадки, снег, ветер; 1-2 взаимодействия с часом | Сетка погоды/остановка; прогноз на целевой час | P0; конкурсный ретро-режим отдельно от operational fallback |
| Перекрытия и ремонты | Пересечение с маршрутом, доля затронутого участка, время до начала/окончания | Геометрия и срок действия | P1 при доступном архиве; иначе честный сценарий известного события |
| Мероприятия | Начало/конец, расстояние до остановки, категория, проверенная оценка масштаба | Зона охвата и временное окно до/после | P1 при достаточном покрытии; несколько проверенных событий лучше неподтверждённого потока новостей |
| Дорожный трафик | Отношение текущего/обычного времени движения, скорость, задержка | Реально общие с трамваем участки | Проверка доступа сразу, внедрение P2; без истории не заявлять backtest-эффект |
| Изменения предложения | Известное расписание, интервал, закрытие остановки, открытие маршрута | Маршрут/направление и версия расписания | После подтверждения в данных; историческая геометрия обязательна |

Один и тот же ремонт из двух новостей дедуплицируется. Географический радиус влияния события (например, кандидаты 500/1000 м) и временные окна выбираются на обучающей части; они не подбираются по окончательному holdout. Посещаемость не угадывается по типу события. Трафик на соседнем шоссе не автоматически влияет на трамвай с обособленным полотном.

## 3. Начальный реестр источников

Проверка веб-страниц выполнена 25.09.2026. «Документация доступна» не означает,
что скачан подходящий архив, проверена квота или измерен эффект. Даты реального
набора подтверждены аудитом: история target 01.01–31.10.2025, прогноз
01.11–31.12.2025.

| Источник | Способ получения и состояние | Что обязательно проверить |
|---|---|---|
| [Датасет организаторов](https://disk.yandex.ru/d/DiFwlfMOauxjBg) | Ссылка из PDF; через инструмент веб-чтения содержимое недоступно, архив не изучен | Игорь получает файл разрешённым способом; проверяет описание, sample submission и правила |
| [Open-Meteo Forecast](https://open-meteo.com/en/docs) | Документация погодного API; кандидат для будущих часов | Покрытие Москвы/периода, модель, единицы, условия использования и допустимость доступного тарифа |
| [Open-Meteo Single Runs](https://open-meteo.com/en/docs/single-runs-api) | Страница прочитана; выбор конкретного выпуска по времени инициализации | Покрытие исторических дат и реальное время доступности выпуска; архив разных моделей имеет разную глубину |
| [Open-Meteo Historical Forecast](https://open-meteo.com/en/docs/historical-forecast-api) | Страница прочитана; сшитый временной ряд прогнозных моделей | Сам по себе не доказывает, что значение было доступно на нужном lead time |
| [Официальный перенос выходных 2025](https://government.ru/docs/all/155500/) | Официальный документ проверен; календарь F01 реализован и провалидирован | Сверять конкретный год; каникулы и местные события остаются отдельными факторами |
| [Изменения движения Москвы](https://i.transport.mos.ru/perekrytiya) | Страница прочитана; календарь объявлений | Наличие исторических публикаций и времени объявления; наличие API не подтверждено |
| [Карта перекрытий](https://transport.mos.ru/mostrans/closures) | Найдена официальная страница в поиске; прямое чтение не удалось | Архив, разрешённый экспорт, геометрия, направление действия и воспроизводимость |
| [TomTom Traffic API](https://docs.tomtom.com/traffic-api/documentation/tomtom-maps/v1/product-information/introduction) | Прочитана документация; кандидат для дорожного трафика | Фактическое покрытие Москвы, ключ, стоимость, архив, лицензия и доступность из среды; не считать гарантированным источником |

Для мероприятий сначала использовать официальное объявление организатора/площадки или транспортного портала с датой, местом и временем. Универсальный источник с подтверждённым историческим покрытием пока не выбран. Для географии сначала использовать справочники организаторов; портал открытых данных Москвы - резервный кандидат, доступность выгрузки не подтверждена.

Разрешённый ручной ввод нескольких событий в локальный реестр допустим для MVP: URL, заголовок, опубликовано, начало/конец, координаты, метод разметки, кто проверил. Синтетическое событие для демо помечается synthetic и не входит в доказательство качества.

## 4. Контракт адаптера

На каждый источник - отдельный адаптер получения и нормализации. HTTP backend не ходит к поставщику синхронно. Получение сохраняет локальный snapshot и manifest; повтор из snapshot воспроизводит признаки без сети.

Обязательные поля нормализованного фактора: source_id, source_url, source_version, feature_name, value/unit, geometry либо entity_id, valid_start/end, issued_at, available_at, fetched_at, quality_status. Отсутствующее поле не заполняется выдуманным значением; допустимость источника решается до обучения.

Для MVP предлагаются таймаут получения 10 секунд и максимум 2 повтора с задержкой; настройки вынести отдельно. Обновление прогноза погоды ориентировочно раз в час, событий - раз в несколько часов, календаря - по изменению версии. Фактический режим согласуется с лимитами и доступностью источника; произвольные частые запросы не нужны.

TTL свежести определяется отдельно для источника и горизонта. При истечении TTL статус становится stale; возможен предыдущий snapshot, только если такой режим предусмотрен моделью. При отсутствии признака не подставлять «0 осадков» или «нет события», если на деле неизвестно. Использовать обученное правило пропуска и индикатор missing либо fallback без источника.

## 5. Защита от утечки будущего

Для прогноза на завтра допустима погода из выпуска, доступного сегодня, а не фактическая погода завтра. Время инициализации погодной модели может быть раньше времени публикации: учитывать задержку доступности. Если исторические выпуски недоступны, честно отделить эксперимент на фактической погоде как верхнюю оценку от реалистичного backtest; основной результат считать без недоступной информации.

Для месяца и года нет основания использовать точную почасовую погоду всего горизонта. Использовать сезонные нормы, доступный горизонт погодного прогноза и отдельные допущения; метод отмечается для каждой части периода.

Новость о перекрытии, опубликованная после события, не является допустимым входом более раннего прогноза. Событие, известное заранее, привязывается к дате публикации и к периоду действия. Современную схему маршрутов не применять к старому периоду без проверки.

## 6. Проверка эффекта и решение о включении

Один протокол временных фолдов, одна целевая величина, одинаковое покрытие оценочных строк и фиксированные настройки сравнения. Последовательно: базовая модель → календарь → погода → события/перекрытия → трафик. Затем по возможности убрать каждую группу из лучшей модели, чтобы увидеть её вклад при взаимодействии с другими.

Таблица эксперимента: experiment_id, версии/seed, фолды, объём, покрытие источника, WAPE-score, MAE, разница с контролем, влияние на пики/маршруты, время обучения/инференса и решение. Плюс на одном случайном разбиении недостаточен. Желателен согласованный положительный эффект минимум на двух временных окнах без значимого ухудшения ключевых срезов; маленький/нестабильный эффект помечается неопределённым.

При отсутствии сопоставимого архива источник остаётся контекстом/сценарием, а не автоматически «улучшает точность». В презентацию попадают только фактические результаты. Нельзя суммировать отдельные приросты как гарантированный общий эффект или объяснять корреляцию причинностью.

## 7. Реализованное конкурсное уточнение 2026-09-25

Для локального ML batch действуют два режима: `operational` с обычной проверкой
`available_at <= as_of` и `competition_retro`, где по уточнению организаторов
разрешены позднее опубликованные внешние факторы. Исключение не распространяется
на будущий пассажиропоток и скрытый ground truth. Защита раздела 5 сохраняется
для продукта и всех operational-оценок.

Полный машинно-читаемый реестр F01–F16 находится в
[`ml/external-sources.json`](../../ml/external-sources.json). Каждая группа имеет
владельцев, статус, роль, режим, источник-кандидат либо явный блокер. Статус
главной страницы не считается доступным архивом.

Фактически проверены по одинаковым temporal folds:

| Группа | Покрытие | Режим | Эффект selection | Решение |
|---|---|---|---|---|
| F01, официальный календарь 2025 | все даты, 10/10 маршрутов | operational | +0,03804 rounded WAPE-score к calendar HGBT | включён |
| F02, ERA5 одной московской grid point | 8 760/8 760 часов, 10/10 как общегородская аппроксимация | competition_retro | −0,00681 rounded score к F01 | исключён |

У F02 `snow_depth` был полностью пуст и исключён без импутации; остальные
обязательные поля покрывают январь–декабрь. Сырой/нормализованный snapshot и
manifest с checksum хранятся локально в `artifacts/`, не в Git. Эксплуатационная
погода не реализована: в эксперименте нет архива прогнозных выпусков, доступных
на соответствующий `as_of`.

F03–F16 не названы интегрированными. Для них не подтверждены требуемый архив 2025,
геопривязка, доступ/лицензия или полнота; решения и точные блокеры перечислены в
реестре. Автоматический мониторинг и сборщики по расписанию не создавались.
