## Сопоставление с TramFlow

**Главный незакрытый вопрос — исполнение модели при проверке.** В
[`ml/model.py`](../../ml/model.py) B2 обучает два HGBT и смешивает их прогнозы.
Это обучаемая ML-модель. В [приёмке B2](b2-acceptance.md) зафиксированы два
независимых CLI inference без fit в чистой venv: float и DS совпали побайтно.
Эти проверки выполнены 26 сентября; здесь они не запускались повторно.

При этом [`backend/handoff/store.py`](../../backend/handoff/store.py) загружает
проверенный CSV в snapshot, а HTTP query делает выборку/агрегацию этого snapshot.
`model.joblib` проверяется по checksum, но не исполняется backend. Существующий
Docker-запуск и независимый CLI inference не доказывают потоковый ML inference
в контейнере. Мониторинг внешних источников также не закрывает этот вопрос:
он не участвует в вычислении конкурсного прогноза.

Текущую поставку нельзя объявлять соответствующей новой потоковой проверке
только потому, что API отвечает онлайн. Вместе с тем из пересылки нельзя
заключить, что требуется обучение на каждом запросе, Kafka или отказ от
кэширования. Формат проверки и применимость объявления к нашему треку неизвестны.

| Артефакт | Уже есть | Что проверить перед сдачей |
|---|---|---|
| A1, ML | Исходный B2, код train/inference, manifests, два clean inference, описание ограничений происхождения | Способ независимого запуска модели в среде проверки; соответствие лучшему отправленному результату |

| A4, архитектура | [Схема](../architecture.md), [контракт](contract.md), [ограничения](limitations.md) | Явно показать отдельные обучение/inference и выдачу готового CSV, диапазон дат/маршрутов, адаптацию и зависимости |
| A5, замеры | [Базовый load](../verification-load.md), [B2-сценарный smoke](verification.md), код k6 и описанные локальные raw-логи | В комплекте должны быть доступны сами доказательства, не только локальные пути; результаты относятся к разным профилям/версиям |
| A6, ограничения | [Документ](limitations.md) и планы развития | Дополнить финальное описание статусом потоковой проверки, не называть план реализованным |

Базовый тест 25 сентября: 199,967 RPS, p95 9,310 мс, 5 минут на ступени 200,
2 CPU / 4 GiB, один worker. Это предыдущий пакет и локальный путь
k6 → Vite → FastAPI. B2-сценарный smoke 26 сентября: 199,945 RPS,
p95 16,042 мс, 60 секунд. Оба измеряют выдачу/агрегацию готового прогноза,
не работу ML и не VPS/Caddy. Их нельзя объединять в один результат.
