# Внешние данные и их роль

Состояние комплекта на 27.09.2026. Ниже разделены конкурсная модель C01, веб-модель B2 и текущий мониторинг. Наличие источника в интерфейсе само по себе не доказывает улучшение модели.

## Что входит в конкурсную модель

| Источник | Для чего используется | Где взять и что сохранено |
|---|---|---|
| Календарь РФ 2025: выходные, праздники и переносы | Календарные признаки B2 и родительской цепочки C01 | [Постановление правительства](https://government.ru/docs/all/155500/); календарная реализация в `ml/features.py`, паспорт в `ml/external-sources.json` исходников; проверочные материалы в `evidence/web-b2/calendar/` |
| Историческая погода Open-Meteo / ERA5 | Погодный компонент MW01 в цепочке C01 | [Описание API](https://open-meteo.com/en/docs/historical-weather-api), [endpoint](https://archive-api.open-meteo.com/v1/archive). `external-data/weather/`: исходный JSON, нормализованные часы, суточные признаки, manifest и аудит |
| Подтверждённые изменения движения № 7, 17, 50 | Признаки ограничений и восстановления движения в родительских моделях C01 | [Официальный Дептранс](https://transport.mos.ru/), [публичный канал](https://t.me/s/DtOperativno). Каждая запись `external-data/restriction-registry.json` содержит конкретные ссылки на начало/окончание и даты публикаций |

Все эти входы также сохранены внутри `competition/model-package.zip`: реестр в `sources/restriction-registry.json`, погода в `parents/v10/workers/M/sources/`, базовый код в `parents/v10/baseline/workspace/ml/`. Для повторения текущего CSV скачивание с сайтов не требуется.

Погода: одна точка Москвы 55.7558, 37.6173; 8 760 часов 2025 года, МСК. Параметры запроса, координаты ответа, время получения и SHA находятся в manifest. Температура, ощущаемая температура, осадки, снегопад, скорость и порывы ветра; осадки согласованы с накоплением следующего часа. Получено 25.09.2026. Атрибуция сохранённого источника: Weather data by Open-Meteo, CC BY 4.0; ERA5 reanalysis. Условия источника: [Open-Meteo](https://open-meteo.com/en/terms).

Реестр изменений движения содержит выбранные подтверждённые интервалы, а не полную историю сети. Отсутствие записи не доказывает обычную работу маршрута. Частичные ограничения не превращаются автоматически в нулевой поток.

Режим C01 — **конкурсная ретроспектива**: допускаются фактическая погода и поздние уточнения, согласно сохранённому разъяснению, переданному командой. История целевой величины ограничена 31.10.2025. Это не доказательство доступности факторов заранее. В B2 веб-комплекта используется календарь; погода и ограничения C01 не подменяют его признаки.

Эффект факторов: календарная абляция B2 имела положительный результат на одних окнах и отрицательный на другом. Для каждого источника C01 отдельный независимый положительный эффект не заявляется. Полные результаты и отрицательные опыты сохранены в ML-пакете.

## Текущий мониторинг веб-приложения

| Источник | Что показывает | Способ получения |
|---|---|---|
| MET Norway | Погода на ближайшие часы | [Locationforecast](https://api.met.no/weatherapi/locationforecast/2.0/documentation), публичный JSON |
| Дептранс | Перекрытия и плановые изменения | [Перекрытия](https://transport.mos.ru/mostrans/closures), [календарь](https://i.transport.mos.ru/perekrytiya), публичный HTML |
| KudaGo | Мероприятия Москвы | [API](https://docs.kudago.com/api/), публичный JSON |

Мониторинг хранит время получения, ссылки и ошибки. Эти текущие записи не меняют исторический batch. Коэффициенты вводит диспетчер вручную. Дорожные пробки не заявляются подключённым численным фактором. Подробности, интервалы обновления и атрибуция: `backend/monitoring/README.md` в исходниках.

## Организаторские данные и перенос решения

Исходный набор предоставлен организаторами: [dataset.zip по ссылке из задания](https://disk.yandex.ru/d/DiFwlfMOauxjBg). Он не включён в Git или общий архив. ML-пакет содержит агрегированную историю и OOF для воспроизведения; её передают вместе с моделью жюри.

Для нового маршрута нужны достаточная история посадок и подтверждённые справочники. Для другого периода нужны актуальная история, календарь и внешние данные с известным временем доступности, затем новая временная проверка. Рабочий прогноз должен использовать прогноз погоды, доступный на дату расчёта, вместо позднего реанализа.
