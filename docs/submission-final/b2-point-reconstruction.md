## Повтор без обучения

В итоговом комплекте есть `b2-point-reconstruction.zip`. Распаковать его рядом
с `sources.zip`, перейти в `tram-forecast`, установить `ml/requirements.txt`
в Python 3.12 venv, как описано в основном README. Затем:

```sh
OMP_NUM_THREADS=4 OPENBLAS_NUM_THREADS=4 PYTHONPATH="$PWD" .venv/bin/python \
  ../b2-point-reconstruction/inference.py --output-dir ../b2-inference-check
```

Выходной каталог должен отсутствовать. Команда создаёт два point CSV, два DS CSV
и `verification.json`. В архиве приложен исходный `test_submission.csv` с SHA
`71c8126bb51068c936462a170da885bad860fc91a58b3d2ac731876d324d7ec3`;
обучающие labels/raw не включены. Контроль каждого файла — `SHA256SUMS` внутри ZIP.
`probe.py` сохранён как журнал команды первоначального локального fit с её путём
к датасету; переносимый повтор использует `inference.py` и не зависит от Downloads.

## Что остаётся открытым

Побайтно одинаковый округлённый DS не доказывает идентичность исходных весов или
всех исходных float. У нового point-model нет подтверждённого исходного q90:
округлённое число из старого отчёта не превращалось в точные интервалы. Полный
float handoff не создавался; текущий demo и его интервалы не изменены. Новый
model нельзя подключать как готовый `ml-handoff-v1`.

Для полной приёмки D0/A1 ещё нужны исходный G0 с metadata/schema/evaluation/OOF,
интервалами и их происхождением либо отдельно принятый полный новый пакет,
а также receipt для проверки сообщённого 0,84260. Настоящая проверка не присваивает
новой модели platform score. D4 всё ещё требует две командные репетиции,
проверку актуальной платформы и доступа жюри после разрешённого размещения.
