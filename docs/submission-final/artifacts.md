## DS: отдельный контроль

- Полный sample: 14 640 строк, 10 маршрутов, 61 день, все часы, № 5 = 0.
- Файл `ds-candidate.csv`, SHA `505039c95a6c7d9acfb84f9822be9c1427707a9e82ac8e1b03e0cadad8054e94`.
- Даниэль проверил и подтвердил, что `champion.csv` получил **0,84260**. Связь
  с DS SHA принята по подтверждению владельца; новый скриншот показывает
  «Успешно», 26.09 18:50 +03:00, 0,84260. [Приёмка B2](b2-acceptance.md).
  Стабильный ID отправки не виден: номер строки 1 не выдаётся за ID.
- Исходный B2 model дважды дал этот же CSV и float побайтно без fit; все строки
  связаны правилом floor(float+0.5). OOF пересчитаны; это не проверка platform receipt.
- На снимке 26.09 18:50:55 осталось **32 любых / 20 успешных** попыток.
  Это наблюдение на момент снимка; период сброса и актуальные правила по нему
  не определяются. Перед следующей отдельно разрешённой отправкой сверить остатки.
- По переданному PDF: до 36 попыток всего / 24 успешных в день, срок 27.09 23:59 МСК.
  Не считать эти значения свежей проверкой платформы.
- Подтверждение этой DS-отправки сохранено в evidence/score/score-evidence.json.
  Следующая отправка требует отдельной команды; сохранить её собственное подтверждение.

## Форма: отдельный контроль

Разместить утверждённые материалы только по отдельной команде. Затем отдельной
сессией с правами жюри открыть каждое A1–A6, сверить bytes/hash, дату проверки
и запасной локальный комплект. Ограничения исходного training provenance в A1 раскрыть явно; локальная приёмка inference не заменяет доступ по ссылке.
Поля формы подготовлены содержательно этой таблицей; публичные URL пока отсутствуют.
После отдельной команды сохранить самостоятельный receipt формы. Успех DS не
доказывает сохранение формы и наоборот.
