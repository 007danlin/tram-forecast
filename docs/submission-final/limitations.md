# Применимость и развитие

Работает локально: route/hour и route/day за ноябрь–декабрь 2025; день/неделя/месяц,
обзор спроса и общий выбор времени, pinned CSV, ручные постоянные коэффициенты
погоды/события 0,5–1,5, качественный год с тремя допущениями. API выдаёт batch,
не обучает модель и не делает model inference на HTTP-запросе.

Успешные посадки не равны уникальным пассажирам, заполненности, числу высадок или
необходимому количеству вагонов. № 5 — транспортный нулевой fallback без успешной
истории обучения. Сравнение полного спроса отделено от partial/no_data и baseline.
Десять месяцев не подтверждают годовую сезонность. У сценария нет оценённого
интервала неопределённости. Его коэффициенты — ручные допущения, не ML-эффект факторов.

Исторические route IDs связаны с картой только по напечатанному номеру. Схема 2026
не доказывает историческую топологию 2025; stop_id, направления, вместимость,
высадки и расписание не установлены. Значение у карты относится ко всему маршруту.
Не производится распределение спроса по остановкам или пикселям PDF.

S1–S4 пересекаются, сентябрь–октябрь повторно использовался; pristine holdout не
заявляется. Исходный B2 принят локально и связан с float/DS побайтно;
Даниэль подтвердил champion.csv → 0,84260, успешная строка сохранена на снимке. Исходный training
commit/dirty state и полный lock обучения не записаны; inference повторяем.
F01 используется; погодные эксперименты и score-v3 дали отрицательный результат.
Трафик и события без доказанного полезного эффекта не заявляются включёнными.

Развитие после хакатона: подтверждённая остановочная геопривязка, полный год истории,
новые факторы с ablation, проверка operational-доступности источников, высадки и
вместимость для оценки загрузки, диспетчерская оптимизация только после появления
этих данных. Это будущие задачи, не функции текущей поставки.
