## 4. Схема архитектуры, применимость и зависимости

ВСТАВЬТЕ_ССЫЛКУ_НА_КОМПЛЕКТ

Схема — `guides/architecture.md`. Пайплайн: история → признаки → обучение → сохранённая модель → batch-прогноз → проверка пакета → FastAPI → React → CSV. Для новых маршрутов нужны история и справочники, для новых периодов — свежие данные, доступные на дату прогноза, обучение и независимая проверка.

## 5. Производительность и дополнительные возможности

Выдача готового прогноза: локальный Docker, FastAPI с 1 worker, 2 CPU / 4 GiB, нагрузка 200 запросов/с в течение 5 минут; фактически 199,967 запросов/с, p95 9,310 мс, 0 ошибок. Сценарий с двумя поправками: 199,945 запросов/с, p95 16,042 мс, 0 ошибок за 60 секунд. Это HTTP-выдача готовых данных, не расчёт ML. Полный B2 inference в Docker на VPS Linux AMD64, 2 CPU / 4 GiB без swap: 14 640 строк за 10,75–11,26 с; максимальный RSS 186,80 MiB. На C01 эти замеры не переносятся. Протоколы: guides/performance.md и evidence/web-b2/ в комплекте.

Дополнительно реализованы: обзор маршрутов, выбор времени и карта, день/неделя/месяц, график и таблица, CSV выбранного результата, четыре ручных коэффициента с отдельным сценарным CSV, автоматический мониторинг городских источников, качественные сценарии на год и план проверки по кварталам. Интерфейс помогает выбрать маршрут и интервал для проверки выпуска.

## 6. Ограничения и развитие после хакатона

Модель оценивает успешные посадки, а не заполненность вагона. Нет подтверждённой привязки валидаций к остановкам, направлениям, высадкам, вместимости и расписанию; значение на карте относится ко всему маршруту. № 5 — нулевой baseline. Численный годовой прогноз не проверен; годовые сценарии качественные, ручные поправки являются допущениями. C01 использует историческую погоду и сообщения о движении в ретроспективном режиме конкурса; в вебе пока B2. Проверочные окна использовались повторно. API выдаёт batch, потоковый ML и несколько реплик не проверены.

После хакатона: подтвердить остановочные справочники и геопривязку, собрать полный год истории, перейти к доступным заранее внешним данным, измерить эффект каждого источника, добавить мониторинг ошибки и переобучение, проверить масштабирование. Оценка заполненности и рекомендации по числу вагонов — после получения высадок, расписания и вместимости.
