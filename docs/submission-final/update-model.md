# Как обновить комплект после новой модели

Текущая точка возврата: C01 / 0,89003 для конкурса, B2 / 0,84260 для веба. Существующие ZIP, модели и CSV не перезаписываются.

1. Получить от Георгия полный пакет: веса всех компонентов, код обучения и расчёта, зависимости, template, float, конкурсный CSV, метаданные, источники, контрольные суммы и команду повторения. Нужен весь пакет зависимостей, не один CSV.
2. Проверить SHA и повторить расчёт в новом каталоге. Сверить 14 640 ключей и их порядок с оригинальным sample, неотрицательные целые, нули № 5, единственное округление из float. Зафиксировать точное совпадение и ограничения. Прежний score не переносить на новые байты.
3. Записать новую версию и результат в реестре лидера. Обновить `model-current.md`, `external-data.md`, `submission-fields.md`, корневой README и `INTEGRATION.md`. Если результат ещё неизвестен, так и написать.
4. Собрать новые исходники и архив по командам ниже в новом каталоге. Упаковщик требует явно назвать кандидата, проверяет SHA по реестру и не меняет веса. Для новой схемы пакета сначала проверить и обновить список входов внешних данных и команду inference.
5. Если модель меняется и в вебе, отдельно подготовить совместимый handoff с float и корректными метаданными, принять его штатным импортёром, проверить UI/API/CSV и перезапуск. Текущий упаковщик сохраняет B2 и не конвертирует C01 автоматически. Несовместимый контракт согласовать с владельцем принимающей части.
6. После разрешённой загрузки заменить ссылки/тексты формы на одну новую версию и проверить сохранение. Старую папку оставить резервом.

## Повторить упаковку текущей версии

Из Git checkout проекта. Нужен Python с backend-зависимостями для независимой проверки handoff; `.venv` — существующая рабочая среда. Каталоги `sources-next` и `delivery-next` должны быть новыми.

```sh
.venv/bin/python -m scripts.package_submission_prep \
  --output-dir artifacts/submission-prep-next/sources-next \
  --include-list docs/submission-final/source-allowlist.json
.venv/bin/python -m scripts.build_upload_bundle \
  --sources artifacts/submission-prep-next/sources-next/web-handoff-preparation.zip \
  --web-bundle artifacts/final-closure-20260927-r01/final-delivery \
  --candidate V11-C01 \
  --output-dir artifacts/submission-prep-next/delivery-next
```

Это собирает материалы и проверяет целостность. Свежая техническая приёмка не возникает из упаковки: `--verification-dir` добавляет отдельный каталог логов, привязанный к SHA `sources.zip`. Приёмка прежнего B2 остаётся датированной историей. Перед загрузкой выполнить команды `web-launch.md` из распакованного архива и повторить C01 по `model-current.md`; результаты сохранить отдельно.

Полный архив `delivery-next.zip` и соседняя SHA256 создаются локально. Скрипты ничего не отправляют на Диск, платформу или сервер.
