# Данные — Игорь

Формат реальных данных организаторов описан в аудите Георгия; сами данные
не добавляются в репозиторий и отсутствуют в этой рабочей папке.
Аудит здесь не повторялся. Агрегированные результаты находятся в
[ml/reports/data-audit.md](../ml/reports/data-audit.md).
Нельзя автоматически публиковать материалы организаторов: сначала изучите правила и разрешения.
Исходные и обработанные данные храните внутри этой директории локально; Git по умолчанию игнорирует всё, кроме этого README и явно разрешённой директории `synthetic/` для будущих проверенных примеров.
Текущий синтетический пример `ml/forecast.py` по-прежнему проверяет HTTP-связку и
не подменяет реальную модель. Потоковая сборка target, temporal backtest, batch
inference и submission-адаптер реализованы в `ml/`; команды описаны в
[ml/README.md](../ml/README.md). Для готового CSV реализован отдельный
[handoff-контракт](../backend/handoff/README.md); общий v2, привязка справочников
к карте и полная приёмка UI/API/CSV остаются на согласовании.
Контракты и изменения фиксируются в [INTEGRATION.md](../INTEGRATION.md).

организаторов либо источник расписания с явно указанным периодом действия.

### Девять маршрутов модели и десять маршрутов submission

[Позднее QA-дополнение](../docs/team-specs/georgy-qa-addendum.md) задаёт девять
маршрутов модели: `1,7,11,12,17,25,26,28,50`. README датасета (§ 4, 6) требует
десять, включая `5`, и полную сетку `10 × 61 × 24 = 14 640` строк.
Наличие этих ключей в локальном sample ранее подтверждено в
[QA-отчёте](../ml/reports/qa-addendum-2026-09-26.md).
26.09.2026 Даниэль передал разрешение организаторов заполнить № 5 нулями
или придуманными значениями. Для следующей серии принят нулевой fallback:
sample сохраняется целиком, 14 640 строк; № 5 не обучается. Согласование состава
submission больше не блокирует работу. Девятимаршрутный экспорт остаётся
диагностическим, прежние статусы конфликта в коде требуют обновления по
[ТЗ Георгию v3](../docs/team-specs/georgy-score-v3.md).
Нулевой fallback № 5 не означает подтверждённого отсутствия движения.

### Как использовать страницу расписаний

[Расписание на Едином транспортном портале](https://transport.mos.ru/transport/schedule)
предложено Игорем для дополнительной проверки ночных часов. Без подтверждённого
периода действия оно не задаёт строгую маску для истории января–октября 2025
или прогноза ноября–декабря 2025. Текущие часы движения сами по себе не определяют
число успешных валидаций. Ночные события не удаляются и прогнозы не обнуляются
только на основании этой ссылки; все часы выбранного submission scope сохраняются.

При проверке 26.09.2026 страница обнаружена в веб-поиске, но прямое чтение
завершилось таймаутом. Конкретные часы и историческое покрытие не подтверждены.
Для применимого правила нужны маршрут, направление, дни недели, точные даты
и часы действия, источник и временная зона; отдельно проверяются переход
через полночь и неполные часы. Даже подтверждённое расписание само по себе
не доказывает, что каждая валидация вне него технологическая.
Очистка обучения остаётся отдельной проверкой по принятой
[схеме маски](../ml/README.md); официальный оценочный target не изменяется.

Даниэлю для уточнения у организаторов: что означают поля дат и `service_id`; где получить
календарь действия и исторические расписания за нужные месяцы 2025 года.

Для повышения score приоритетнее закончить исторические интервалы изменений
маршрутов 7/17/50: [реестр источников](../docs/team-specs/score-v3-sources.md).
В [аудите 26.09](../ml/reports/score-audit-2026-09-26.md) повторно проверены
labels/sample и обучены контрольные модели; это отдельная проверка после
описанной выше сверки README, без повторного полного сканирования raw.
