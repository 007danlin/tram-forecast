# Frontend — Артём

Одна страница React: шапка с навигацией (Карта/Аналитика/Настройки), верхняя панель фильтров,
карта, плавающая карточка прогноза слева снизу и нижняя временная панель. Загрузка, ошибка,
повтор запроса, SVG-график и таблица встроены в карточку и в раздел «Аналитика».
Настройка прокси и команды: [INTEGRATION.md](../INTEGRATION.md).
Зависимости зафиксированы в `package-lock.json`; устанавливайте через `npm ci`.

## Оболочка интерфейса (`src/App.tsx` и `src/components/`)

Карта — полноэкранный фон под шапкой; фильтры, карточка прогноза и таймлайн — плавающие
полупрозрачные панели поверх неё. Тема одна (светлая) — токены в `style.css`, `prefers-color-scheme`
сознательно не используется.

- `AppHeader` — логотип, бейджи «ДЕМО» и статус соединения с backend, навигация Карта/Аналитика/Настройки.
- `FilterBar` — компактная однострочная полоска (высота ~60–70px, ширина по контенту, не во весь
  экран): маршрут/остановка/дата/горизонт с маленькими иконками, каждое поле ~36px высотой.
  Направление и «Сбросить фильтры» вынесены в поповер по кнопке «⋯» (закрывается по клику вовне
  или Escape), чтобы не раздувать основную строку. В v1 все контролы, кроме горизонта «1 день»,
  отключены с пояснением «Требуется подключение данных и фильтров API» — v1-API не принимает
  параметры запроса. На виде «Карта» — плавающая панель поверх карты (`overlay`), на «Аналитике» —
  обычная строка над содержимым. `App.tsx` меряет её реальную высоту через `ResizeObserver` и
  кладёт в CSS-переменную `--filters-height`, чтобы карточка ниже никогда не могла наехать на неё,
  независимо от того, в сколько строк фильтры перенеслись на узком экране (на телефоне поля не
  помещаются в одну строку и переносятся — это неизбежное следствие ширины экрана, не отдельный
  режим вёрстки).
- `Workspace` — оборачивает существующий `TramMap` (без изменения его внутренней отрисовки, только
  внешние `.tram-map`/`.tram-map__stage`: ширина/высота/позиция на 100% контейнера) и накладывает
  карточку/кнопку открытия/таймлайн как `position: absolute` слой поверх. Заголовок и пояснение,
  которые рисует сам `TramMap`, визуально скрыты (`sr-only`, доступны скринридеру), цветовая
  легенда скрыта совсем — каждая линия и так подписана прямо на схеме. Карта не перемонтируется при
  открытии карточки, смене вкладок, обновлении прогноза или переключении Карта/Аналитика (переключение
  view скрывает `Workspace` через `display:none`, а не убирает его из DOM).
- `ForecastCard` — вкладки «Прогноз/По участкам/О маршруте», переключатель График/Таблица,
  статус и раскрываемые «Факторы и ограничения», действия «Обновить/CSV/Сценарий» (CSV и
  Сценарий отключены до соответствующего backend). Показывает только то, что реально приходит из
  v1-API (`is_mock`, `unit`, `points`) плюс честные производные величины (число точек, максимум
  ряда); полей без источника (сравнение с обычным уровнем, время в пути) нет — значения с
  референсного скриншота (маршрут 39, 1520 пасс./час и т.д.) в код не переносились.
- `TimelinePanel` — воспроизведение и шкала по загруженным точкам (шаг 15 минут; часовой шаг
  показан отключённым до появления часовых данных). Не отправляет новый запрос на каждый шаг.
- `SettingsPanel` — боковая панель: режим данных, реально реализованные настройки (пока нет) и
  список недоступного с причиной.
- `AnalyticsView` — увеличенный график и полная таблица того же результата, обычная (не полноэкранная) страница.

Этап 1 (сделан): вся эта оболочка, честный демо-режим, адаптив 1366×768 и мобильный. Этап 2
(после согласования API v2): реальные значения фильтров, часовые/месячные/годовые горизонты,
маршрутные показатели, CSV-экспорт, диспетчерские сценарии.

## Карта трамваев (в разработке)

Линии маршрутов рисует само приложение (SVG из осевых линий, извлечённых из PDF); ни растра, ни копии PDF в браузере нет; pan/zoom — колесо, перетаскивание, pinch, кнопки, клавиатура.
Схема заполняет контейнер целиком (`object-fit: cover`-подобное поведение — `fit = Math.max(w/pageW, h/pageH)` в `TramMap.tsx`, вместо `Math.min` "contain"), без пустых полей на любом соотношении сторон; при `MIN_ZOOM` обрезаются края, а не остаются пустыми. Стартовый вид — центр на «Чистые пруды» с приближением (`DEFAULT_CENTER`/`DEFAULT_ZOOM` в начале `TramMap.tsx`), а не вся схема целиком мелко; кнопка/клавиша «0» возвращает к этому виду (её подпись и `aria-label` обновлены — раньше она буквально показывала всю схему, сейчас это уже невозможно без пустых полей).

Под схемой — просто заливка страницы (`--map-land` в `style.css`), без декоративного фона. По ходу задачи пробовали: реальные тайлы OpenStreetMap через Leaflet (визуальный шум, конфликт с подписями схемы) и рисованную векторную подложку «город» — сначала без учёта данных схемы (кварталы/река пересекали линии), затем с occupancy-сеткой по реальным координатам линий/подписей/остановок из `network.json`, чтобы ничего не пересекалось. По результату решили, что декоративный фон в любом виде не нужен — оставили только заливку. Тема одна (светлая).
Ресурсы карты локальные и в Git не попадают (`frontend/public/map-local/`, исходный PDF — `data/tram-map/`). Получение:

```sh
pip install -r scripts/map/requirements.txt
python scripts/map/extract_lanes.py             # читает data/tram-map/trammap_15_04_26-2.pdf
```

Без этих файлов сборка проходит, а карта показывает сообщение о необходимости подготовки. Интерактивный выбор маршрутов и остановок ещё не реализован.

Номера маршрутов на линиях и цветовая легенда получаются вторым шагом (после `extract_lanes.py`):

```sh
python scripts/map/label_lanes.py   # распознаёт номера на линиях по эталонам из легенды PDF, дописывает routes/legend в network.json
```

Линии без надписи на схеме получают номер по соседям или по ручному списку `OVERRIDES` в скрипте; такие линии помечены `inferred` и требуют проверки.

Остановки и подписи (все линии):

```sh
pip install winocr                   # только Windows 10/11 с языком OCR «ru»
python scripts/map/build_stops.py    # точки остановок и подписи из PDF, тексты — OCR
```

Точки — круги на осевых линиях; подписи — тёмные контуры текста из PDF, повёрнутые под тот же угол; тексты распознаются OCR (текст в PDF переведён в кривые).
Исправления OCR — в локальном `data/tram-map/stop-overrides.json` (`{"text": {"как распознано": "как правильно"}, "at": [[x, y, "текст"]]}`). Отчёт со спорными местами: `data/tram-map/stops-report.json`. Подпись привязана к точкам по геометрии; остановки не объединяются между линиями автоматически.

Достопримечательности и значки метро/МЦК:

```sh
python scripts/map/build_icons.py    # контуры иллюстраций и значков «М» из PDF -> network.json (landmarks, metro)
```

Иллюстрации (МГУ, Кремль и др., с подписями) и значки станций рисуются как векторные контуры из PDF, сгруппированные в объекты; в Git они не попадают.
