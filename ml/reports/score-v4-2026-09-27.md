# Score v4: измеренная ограниченная серия, 27.09.2026

Решение: **сохранить исходный B2**. Цель около 0,95 на платформе не достигнута.
Лучший измеренный новый результат на S1–S4 — **0,84565649**, Δ **+0,00081500**,
у фиксированной смеси 50% B2 / 50% B2-cal. Это ниже допуска +0,002; улучшены
только 2/4 окна вместо требуемых ≥3/4. Снижение SAE равно 36 317 посадок,
или 0,5253% от SAE B2. Платформенный эффект этой смеси неизвестен.

## Origins и ограничения внутренней настройки

Для A общие B2-прогнозы строились из истории до каждого origin и кэшировались.
На S1/S2/S3/S4 соответственно 10/16/22/28 origins с шагом 5; во всех представлены
все семь дней недели. Признак состояния — отношение медианы последних 14 суток
к предыдущим 28 суткам, состояния down/stable/up при 0,9/1,1.
Расширенная модель давности смены режима в этой серии не проверялась.
S1 содержит только частичные внутренние окна, максимум 60 дней; это ограничение
ранних данных, а не полноценная внутренняя 61-дневная проверка.

После аудита внутренняя настройка A1/A2 использует один фиксированный origin
и только train-targets до него: 05.04 / 30.04 / 20.05 / 14.06. Проверочные
хвосты имеют 25/31/41/47 дней. Последующие факты не подставляются в признаки.
Финальная для внешнего окна калибровка обучается на всех доступных до cutoff OOF.
Частичные горизонты и коррелированные targets ограничивают качество настройки.

D1/D2 имеют 11/17/23/29 origins, все weekdays, и используют исходный v3
temporal target-date split для числа итераций. Его validation объединяет
обновляющиеся origins и **не называется fixed-origin проверкой**. Это сохранено
для чистого сравнения с v3 D-MAE; внешние S-окна всегда fixed-origin на 61 день.
У D2 эффективные веса всех 61 горизонта одинаковы до машинной точности;
правило зависит только от сетки и duplicate counts. Прежний D-MAE
0,79800253: D1 Δ −0,00053006, D2 Δ +0,00041950 к нему. Дальнейшей сетки direct нет.
Полные таблицы `dow × horizon` и effective mass сохранены в `audit.json`.

## Нейромодель, статистика, стоимость и внешние источники

Chronos-2 запущен локально, CPU float32, zero-shot, 61 суточный шаг.
[Официальная модель](https://huggingface.co/amazon/chronos-2), revision
`29ec3766d36d6f73f0696f85560a422f50e8498c`, Apache-2.0.
SHA config: `ef1143bfdc9c0376d9a056eefca46cb4b1ec3d0ffacd541ff56feb40fb708031`;
SHA weights: `ddcda3c7508bf2528087723e98a20707cc04b7f370ae275a9fd88078ddba4f42`.
Весовой файл около 456 MiB. Веса скачаны из Hugging Face; датасет стороннему
inference API не передавался. Known-future covariates: dow, is_day_off,
is_public_holiday, годовые sin/cos. Других внешних факторов нет.

Технический smoke N2 S4: загрузка/получение модели 258,46 s, inference 0,289 s,
peak RSS 1,20 GB; все значения конечны. Smoke использовал default
cross_learning=False и дал 0,77063803. Полный N1/N2 использует
cross_learning=True; у N1 API группирует 24 targets по маршруту.
Smoke не используется как дополнительный quality-кандидат.
Полный inference четырёх окон: N1 3,39 s, N2 0,91 s; peak RSS 1,17 GB.
Источник точечной оценки — документированный median `predictions`.
Fine-tuning/Bolt не запускались, поскольку основной smoke технически успешен.

C1/C2 — [StatsForecast AutoETS](https://nixtlaverse.nixtla.io/statsforecast/src/core/models.html#autoets),
`model=ZZZ, season_length=7, damped=True`. На официальных праздниках/переносах
и рабочей субботе заранее задан fallback B2 соответствующего origin.
C2/N2 используют прогнозную форму этого B2; при нулевой сумме — 1/24 на час.
C1 занял 21,95 s, C2 5,30 s по четырём folds, peak RSS 0,25 GB.

Начальная подготовка внутренних B2 OOF и A1: около 297 s; A2 повторно использует
кэш. D1 227,23 s, D2 226,88 s. Это измерения конкретного CPU, не SLA.
Основное окружение: Python 3.12.14, numpy 2.3.3, pandas 2.3.3, sklearn 1.7.2,
CatBoost 1.2.8. N: chronos-forecasting 2.3.2, torch 2.14.0, transformers 5.17.0;
C: statsforecast 2.1.1. Полные freeze/версии/SHA вложены в локальную поставку.
Исследовательские окружения отделены от API и не являются новым production runtime.

## Исправления и отклонения от протокола

1. Первый split A1/A2 делил origins, но не исключал пересечение target-дней;
   A1 не имел усадки корневого коэффициента к 1. Исправлено без изменения
   сетки bounds/shrinkage; raw OOF и модели первого прохода сохранены,
   окончательные A1/A2 — в `protocol-repair/`. Первые score 0,83753844 /
   0,84045984 заменены в итоговом сравнении на 0,83821099 / 0,84194466.
2. Daily-диагностика первого прохода округляла raw сумму. Итоговая версия
   суммирует округлённые часы; основной hourly score не менялся.
3. Calendar month приведён к исходным меткам B2. B1/B2-cal повторены:
   внешние прогнозы побайтно/численно сохранились. Не вводилась новая гипотеза.
4. Однократная ad-hoc команда посчитала смеси N1 и D2 с теми же тремя весами,
   сверх разрешённых двух blend-кандидатов. Это реальное отклонение, а не
   часть заранее фиксированной серии. Все шесть не прошли допуск и исключены
   из выбора; значения и reasons сохранены в `audit.json`. Максимальные Δ:
   N1(0,10) +0,00024834, D2(0,10) +0,00043563. Новых blend-переборов нет.

Из-за раскрытого отклонения серию нельзя называть идеально preregistered.
Пороги не смягчались, внешние факты/платформа для подбора не использовались.
