# Протокол адаптивной корректировки № 50

Зафиксирован до первого вычисления результатов адаптивного правила.
Конфигурация: `ml/experiments/route50-adaptive.json`. Одна гипотеза, без сетки
порогов/весов и без ручной даты смены режима. История уже исследовалась в
предыдущих опытах: предварительная фиксация не делает данные независимым тестом.

На каждом origin O используются только даты < O. Обычный выходной имеет то же
определение, что в предыдущем эксперименте: суббота/воскресенье, исключая
официальные праздники, переносы и рабочие выходные.

1. Эталон прежнего уровня: медианный суточный поток отдельно для субботы и
   воскресенья в [O−112 дней, O−28 дней). Нужно ≥6 дат каждого типа.
2. Свежий уровень: средний суточный поток отдельно для субботы и воскресенья
   в [O−28 дней, O). Нужно ≥3 дат каждого типа и полные 24 часа.
3. Оба свежих средних должны быть ≤35% соответствующего положительного эталона.
4. Каждый из шести дней последних трёх полных обычных уикендов также должен
   быть ≤35% соответствующего эталона. Уикенды идут подряд через 7 дней;
   для каждого известны суббота и воскресенье, целиком до O.
5. Только при всех условиях применяется 100% прежнего 4-недельного среднего
   почасового профиля отдельно по субботе/воскресенью. Иначе исходный B2.
   Решение и профиль заморожены на весь прогноз из O. При возврате спроса
   выше условия в следующем origin коррекция отключается; постоянной защёлки нет.

Медиана нужна для сравнения уровней, она не является удалением наблюдений.
Профиль включает все пики и нули. Никаких ручных закрытий или обнуления.
При недостаточной истории переключение выключено; повреждённая часовая сетка
останавливает расчёт. Праздники, 01.11, будни и остальные маршруты не меняются.

Основная проверка: прежние S1–S4 и D по 61 дню, плюс прежний C (октябрь из 01.10,
31 день). Дополнительно origins 08/15/22/29.09: B2 обучается заново до каждого O,
прогноз формируется из одной точки; оценка ограничена 31.10, без фиктивного
target ноября. Доступные горизонты 54/47/40/33 дня и общий срез 01–31.10.
Правило дополнительно сканируется по всем ежедневным origins до 01.11 для
фиксации реальных дат включения/выключения, но результаты сканирования не
используются для выбора дат оценочных окон или настройки порогов.

Печатаются общий raw/rounded WAPE-score, SAE/MAE/WAPE/score обычных выходных
№ 50, по каждому origin и по часам, решение и использованные даты истории.
Октябрьские задачи разных origins перекрываются: они не складываются в
независимые испытания. Основной дополнительный результат — один прогноз
октября из заранее заданного origin 29.09 (последний сентябрьский origin сетки).
Его однократный учёт даёт 31 уникальную дату и 8 обычных выходных.

Условие **исследовательского** экспорта: ни одно прежнее или дополнительное
окно/октябрьский срез не ухудшается; основной дополнительный score растёт,
SAE выходных № 50 сокращается ≥20%; правило включено на 01.11; preflight
и проверка неизменности остальных клеток проходят. Нулевой эффект там, где
снижение ещё не наблюдалось, ожидаем и допустим. Это новый протокол именно
исследовательского файла, а не ослабление порога замены incumbent из серии v3.

При выполнении условий создаётся отдельный CSV с 14 640 ключами sample,
нулевым № 5, preflight и SHA-256. Исходный файл со score 0,84260 не заменяется;
файл автоматически не загружается на платформу. Положительный октябрьский
эффект не подтверждает сохранение режима на 61 день ноября–декабря.
